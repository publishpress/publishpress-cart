# Missing Core Email Option Resolves To Template Default

## Scenario

When a core email option has never been saved, the canonical option API must return the plugin's template default rather than `false`. After copy-on-read confirms that neither a canonical `_ppcart_email_completed_subject` row nor a leftover `_sc_email_completed_subject` row exists, the `default_option__ppcart_email_completed_subject` filter runs `ppcart_email_template_default_option()`, which looks up the canonical option in `ppcart_email_template_option_defaults()`.

## Steps

1. Ensure no legacy `_sc_email_completed_subject` storage row exists.
2. Call `get_option('_ppcart_email_completed_subject')`, which triggers the canonical `default_option__ppcart_email_completed_subject` filter after copy-on-read misses.
3. `ppcart_email_template_default_option()` finds the canonical key in `ppcart_email_template_option_defaults()` and returns its default.

## Expected result

- `get_option('_ppcart_email_completed_subject')` returns the template default string `Your order from {site_name} is complete!`.

## Edge cases

- This default is the translated `completed` → `subject` default; it is computed lazily here (at resolution time), not during file-load registration.
