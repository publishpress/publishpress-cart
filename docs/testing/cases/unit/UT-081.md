# Late Init Registration Pass Is Scheduled At Priority 99

## Scenario

A single file-load pass cannot see option names that add-ons declare later via the `ppcart_email_template_option_names` filter. To catch those, the module schedules a second registration pass on the WordPress `init` action at priority `99`, after normal add-on setup has run. This case verifies that the late pass is hooked at exactly `init` / priority `99`.

## Steps

1. Load `ppcart-email-template-functions.php`, which runs `add_action('init', 'ppcart_register_email_template_option_filters', 99)` at file scope.
2. Inspect the stub action registry for the `init` hook.
3. Assert the registry contains an `init` entry and that it has a callback bucket keyed at priority `99`.

## Expected result

- The stub actions map has an `init` key, and `actions['init']` contains priority `99`, confirming the late re-registration pass runs at `init` priority `99`.

## Edge cases

- Priority `99` (rather than the default `10`) is deliberate so add-ons that register their option names on earlier `init` callbacks are already declared before this pass re-runs.
