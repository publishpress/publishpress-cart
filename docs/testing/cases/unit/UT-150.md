# Pre-update hook encrypts a sensitive option before it is stored

## Scenario

Security case. When the database encryption flag is on, the `pre_update_option` filter must transparently encrypt the incoming value of a sensitive option so the plaintext credential never reaches `wp_options`. This case feeds a new Stripe secret key through the pre-update filter with encryption enabled.

## Steps

1. Skip if OpenSSL is unavailable, and skip if the `PPCART_ENCRYPT_SECRETS` constant is defined.
2. Enable the database flag (`ENCRYPT_SECRETS_OPTION` = `'1'`).
3. Call `PPCart_Secrets::filter_pre_update_any_option('sk_test_new_key_value', '_sc_stripe_test_sk', '')` (new value, option key, empty old value).
4. Inspect the returned value with `PPCart_Secrets::is_encrypted_value()`.

## Expected result

- The value returned by the pre-update filter for `_sc_stripe_test_sk` is encrypted (`is_encrypted_value()` returns `true`), so the stored option is ciphertext rather than the raw `sk_test_new_key_value`.

## Edge cases

- If encryption were disabled, the same call would pass the value through unchanged (covered by UT-151); the encrypt-on-write behavior is gated entirely on the database flag.
