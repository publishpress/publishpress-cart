# Mailchimp REST client sends authenticated requests and maps errors

## Scenario

Free talks to Mailchimp only through `ppcart_mailchimp_api_request()` on the
WordPress HTTP API. No third-party Mailchimp SDK ships. The client must build
the datacenter URL, send Basic auth, and turn every failure into a `WP_Error`.

## Steps

1. Key `abc123-us1`. Stub `wp_safe_remote_request`. Call
   `ppcart_mailchimp_api_request('lists', 'GET', [], ['count' => 100])`.
2. Respond `400` with a Mailchimp `detail`. POST a JSON body.
3. Respond `500` with a non-JSON body.
4. Respond `200` with a non-JSON body.
5. Return a transport `WP_Error`.
6. Key `abc123-us1.evil.example/`.

## Expected result

1. URL `https://us1.api.mailchimp.com/3.0/lists?count=100`, method `GET`,
   `Authorization: Basic base64(publishpress:<key>)`, no body.
2. `WP_Error` `ppcart_mailchimp_api_error`, message is the `detail`, data
   `['status' => 400]`. The body sent is the JSON of the input.
3. `ppcart_mailchimp_api_error` with the generic message and status 500.
4. `ppcart_mailchimp_invalid_response`.
5. The same `WP_Error` object.
6. `ppcart_mailchimp_invalid_api_key`, and no HTTP request.
