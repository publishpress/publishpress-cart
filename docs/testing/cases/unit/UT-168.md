# Cancellation refund resolves the latest invoice through Stripe

## Scenario

To compute a refundable amount, the cancellation refund flow does not trust the local copy of the invoice; it re-fetches the subscription's `latest_invoice` from Stripe so the paid and credited totals are authoritative. This test verifies the invoice is retrieved exactly once through the Stripe `invoices` service.

## Steps

1. Build a Stripe client stub whose `invoices->retrieve()` counts its calls and returns invoice `in_test` with `amount_paid = 2000` and `post_payment_credit_notes_amount = 500`.
2. Call `ppcart_issue_stripe_subscription_cancellation_refund()` with order `{ id: 321, subscription_id: 'sub_test' }` and Stripe subscription `{ id: 'sub_test', latest_invoice: 'in_test' }`.
3. Inspect the stub's `invoices->retrieve_count`.

## Expected result

The latest invoice `in_test` is fetched through Stripe, so `invoices->retrieve_count` equals `1`.

## Edge cases

- The invoice is resolved from the subscription's `latest_invoice` id, not from any locally stored invoice, ensuring stale local data cannot skew the refund amount.
