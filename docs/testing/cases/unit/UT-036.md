# Debug Log View Verifies The Nonce After The Capability Passes

## Scenario

Security/access-control case. Once a user with `manage_options` requests to view the log, the handler must still verify a request-specific nonce before rendering log contents. This case asserts the handler calls `ppcart_check_admin_referer()` with the canonical view action (`ppcart_view_debug_log`) and canonical query argument (`ppcart_view_debug_log_nonce`), enforcing CSRF protection on top of the capability gate.

## Steps

1. Simulate a request where `$_REQUEST['page']` is `ppcart-settings` and `$_REQUEST['ppcart_view_log']` is `1`.
2. Simulate the current user holding the `manage_options` capability.
3. Stub `wp_verify_nonce()` to record the canonical action, then divert into the render path.
4. Call `PPCart_Debug_Logger::view_log_request()`.

## Expected result

After the capability check passes, the handler invokes the nonce check before rendering: `ppcart_check_admin_referer()` is called with action `ppcart_view_debug_log` and query argument `ppcart_view_debug_log_nonce`, and `wp_die()` is never called. The nonce is verified prior to producing any log output.

## Edge cases

- The nonce action and query-arg names must match exactly; a mismatch would either reject legitimate admins or weaken CSRF protection on the view path.
