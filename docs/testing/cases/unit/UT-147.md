# Database flag turns on at-rest encryption and reports the database source

## Scenario

Security case. An admin opts in to encrypting sensitive options at rest by setting the database flag `ENCRYPT_SECRETS_OPTION` to `'1'`. `PPCart_Secrets` must then report encryption as enabled and identify `database` (not the wp-config constant) as the control source, so subsequent writes of sensitive options are encrypted before they hit `wp_options`.

## Steps

1. Skip if the `PPCART_ENCRYPT_SECRETS` wp-config constant is defined (it would override the database flag).
2. Enable the database flag by setting `ENCRYPT_SECRETS_OPTION` to `'1'` (`setDbEncryptionEnabled(true)`).
3. Read `PPCart_Secrets::is_db_encryption_enabled()`, `PPCart_Secrets::encryption_enabled()`, and `PPCart_Secrets::get_encryption_control_source()`.

## Expected result

- `is_db_encryption_enabled()` returns `true`.
- `encryption_enabled()` returns `true`, so sensitive option writes will be encrypted at rest.
- `get_encryption_control_source()` returns the exact string `'database'`, distinguishing the opt-in from the wp-config constant path.

## Edge cases

- When both the wp-config constant and the database flag could apply, the constant wins; the test is skipped if `PPCART_ENCRYPT_SECRETS` is defined so the database-source assertion remains valid.
