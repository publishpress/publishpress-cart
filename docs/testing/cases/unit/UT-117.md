# Integration Plan Restriction Still Targets The Copied Plan Option ID

## Scenario

An integration can be restricted to specific payment plans via its `int_plan` list, which holds plan `option_id` values. Because plan `option_id`s are preserved on the copy (UT-112), the copied restriction must still resolve to the duplicate's own plan. This verifies the integration's `int_plan` still references `plan_recurring`.

## Steps

1. Seed the source integration with `int_plan` set to `['plan_recurring']`.
2. Duplicate the product (the recurring plan keeps `option_id` `plan_recurring`).
3. Read `_sc_integrations[0]['int_plan']` from the duplicate.

## Expected result

`_sc_integrations[0]['int_plan']` equals `['plan_recurring']`, still pointing at the duplicate's preserved plan option id.

## Edge cases

- This is why plan `option_id`s are preserved rather than regenerated: cross-references inside copied repeaters stay valid on the duplicate.
