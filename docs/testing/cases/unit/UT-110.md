# Payment Plan Rows Are Copied

## Scenario

A product's pricing is stored in the `_sc_pay_options` repeater. The duplicate must receive every payment plan row so its pricing matches the source. This verifies the full set of plan rows is copied.

## Steps

1. Seed the source product with two `_sc_pay_options` rows (a one-time plan and a recurring plan).
2. Duplicate it.
3. Read `_sc_pay_options` from the duplicate via `get_post_meta(..., true)` and count the rows.

## Expected result

The duplicate's `_sc_pay_options` contains 2 rows, matching the source's two plans.

## Edge cases

- Row count is preserved even though Stripe identity fields inside the rows are cleared (UT-113/UT-114); clearing ids does not drop rows.
