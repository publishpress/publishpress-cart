# Foreign Screen Ids Merely Containing "sc" Are Not Plugin Screens

## Scenario

Other plugins create admin pages with ids like `tools_page_my-sc-tool` that happen to contain the substring `sc`. Cart detection must use prefix/exact matching, not loose substring matching, so a foreign tools page is never mistaken for a Cart screen. `PPCart_Admin_Screens::is_plugin_screen()` should reject it.

## Steps

1. Reset the admin screen context with a screen object `{ id: 'tools_page_my-sc-tool', base: 'tools_page_my-sc-tool' }`.
2. Call `PPCart_Admin_Screens::is_plugin_screen()`.

## Expected result

`is_plugin_screen()` returns `false`: the screen id is not a known hook, does not start with the `ppcart_page_` canonical prefix, and is not a known post type/taxonomy — the incidental `sc` substring is irrelevant.

## Edge cases

- Guards against substring false positives; pairs with UT-010 where a genuine `ppcart_page_` prefix does match, isolating prefix-vs-substring behavior.
