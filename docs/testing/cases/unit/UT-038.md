# Debug Log Reset Is Denied Without The manage_options Capability

## Scenario

Security/access-control case. Resetting (clearing) the debug log is an administrator-only action handled by `PPCart_Admin_Settings::page_options()`. When a user without the `manage_options` capability submits a reset request (`sc_reset_log`), the handler must hard-deny via `wp_die()` and must not proceed to nonce verification or clear the log. This enforces the capability gate before any destructive log operation.

## Steps

1. Simulate a request where `$_REQUEST['sc_reset_log']` is `1`.
2. Simulate the current user lacking the `manage_options` capability.
3. Instantiate `PPCart_Admin_Settings` (without running its constructor) and call `page_options()`.

## Expected result

The handler denies the request: `wp_die()` is called (raising the simulated termination) and the nonce check (`check_admin_referer`) is never reached. The `manage_options` capability check fails closed, blocking the reset before any nonce logic or log mutation.

## Edge cases

- The capability denial occurs before nonce verification, so a valid reset nonce cannot let a non-administrator clear the log.
