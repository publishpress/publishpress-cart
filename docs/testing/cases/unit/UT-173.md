# Credit note creation is logged on the subscription record

## Scenario

Issuing a cancellation credit note should leave an audit trail on the local subscription/order so staff can see the refund happened. This test confirms an order-log entry is written to the record's `_ppcart_order_log` post meta when the credit note is created.

## Steps

1. Reset the in-memory `post_meta` store to empty.
2. Build a Stripe client stub whose latest invoice `in_test` has `amount_paid = 2000` and `post_payment_credit_notes_amount = 500`.
3. Call `ppcart_issue_stripe_subscription_cancellation_refund()` with order `{ id: 321, subscription_id: 'sub_test' }` and subscription `{ id: 'sub_test', latest_invoice: 'in_test' }`.
4. Inspect the stored post meta for post id `321`.

## Expected result

Post meta is recorded for post `321`, and that record contains an `_ppcart_order_log` key holding the credit-note creation log entry.

## Edge cases

- The log is keyed to the local order id (`321`); with an empty starting meta store, the `_ppcart_order_log` key is created on first write rather than appended to existing logs.
