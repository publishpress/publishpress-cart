# Missing Addon Email Option Resolves To Addon Template Default

## Scenario

The same default-resolution behavior must extend to add-on options: once an add-on declares its canonical option name and template, an unset add-on option should resolve to the add-on's declared default through the registered `default_option_<option>` filter. This case verifies that an unset `_ppcart_email_runtime_addon_subject` resolves to the add-on default `Addon default`.

## Steps

1. Add a `ppcart_email_template_option_names` filter appending `_ppcart_email_runtime_addon_subject`.
2. Add a `ppcart_email_templates` filter adding a `runtime_addon` template whose `subject` maps to `_ppcart_email_runtime_addon_subject` with default `Addon default`.
3. Call `ppcart_register_email_template_option_filters()` to register the add-on option's filters.
4. With no stored value for `_ppcart_email_runtime_addon_subject`, call `get_option('_ppcart_email_runtime_addon_subject')`.

## Expected result

- `get_option('_ppcart_email_runtime_addon_subject')` returns `Addon default`, resolved by `ppcart_email_template_default_option()` via the add-on-provided `ppcart_email_templates` entry.

## Edge cases

- Default resolution reads from `ppcart_email_template_option_defaults()`, which is rebuilt from the filtered `ppcart_email_templates`, so the add-on default is available only after the add-on's `ppcart_email_templates` filter is in place.
