# Cancellation refund returns the created Stripe credit note

## Scenario

When a subscription is cancelled with a refund, `ppcart_issue_stripe_subscription_cancellation_refund()` creates a Stripe credit note against the subscription's latest paid invoice and hands the resulting credit note object back to the caller. This test confirms the function returns that credit note rather than a boolean or null, so downstream code can read its id and linked refund.

## Steps

1. Build a Stripe client stub whose latest invoice `in_test` reports `amount_paid = 2000` and `post_payment_credit_notes_amount = 500` (cents), and whose `creditNotes->create()` returns `{ id: 'cn_test', refund: 're_test' }`.
2. Call `ppcart_issue_stripe_subscription_cancellation_refund()` with the local order `{ id: 321, subscription_id: 'sub_test' }`, the Stripe subscription `{ id: 'sub_test', latest_invoice: 'in_test' }`, and the stub client.
3. Capture the returned value.

## Expected result

The function returns the Stripe credit note object, and its `id` is `cn_test`.

## Edge cases

- The credit note must be returned even though the order id (`321`) differs from the Stripe subscription id (`sub_test`); the return value follows the Stripe object, not the local record.
