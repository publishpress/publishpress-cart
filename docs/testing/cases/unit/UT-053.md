# Log Event Writes Structured Context For Viewer

## Scenario

The newer `log_event()` API writes an event name plus a structured context array, which the viewer reads back as typed fields. This case verifies that an order id passed in context is persisted and surfaced as the entry's `order_id` after a search.

## Steps

1. Instantiate `PPCart_Debug_Logger` and call `log_event('checkout.order.saved', 'Order saved successfully.', ['order_id' => 701, 'status' => 'paid', 'client_secret' => 'secret_value'], 0)`.
2. Call `PPCart_Debug_Log_Viewer::read_entries(['limit' => 10, 'search' => '701'])`.
3. Inspect the first entry's `order_id` field.

## Expected result

- `read_entries()` returns the matching entry, and `entries[0]['order_id']` is the integer `701`.

## Edge cases

- A `log_event()` call without an `order_id` in context should still write a readable entry, just with a neutral order id.
