# Debug Log Download Verifies The Nonce After The Capability Passes

## Scenario

Security/access-control case. Once a user with `manage_options` requests a log download, the handler must still verify a request-specific nonce before streaming the file. This case asserts the handler calls `ppcart_check_admin_referer()` with the canonical download action (`ppcart_download_debug_log`) and canonical query argument (`ppcart_download_debug_log_nonce`), enforcing CSRF protection on top of the capability gate for the download path.

## Steps

1. Simulate a request where `$_REQUEST['page']` is `ppcart-settings` and `$_REQUEST['ppcart_download_log']` is `1`.
2. Simulate the current user holding the `manage_options` capability.
3. Stub `wp_verify_nonce()` to record the canonical action, then divert into the download path.
4. Call `PPCart_Debug_Logger::view_log_request()`.

## Expected result

After the capability check passes, the handler invokes the nonce check before downloading: `ppcart_check_admin_referer()` is called with action `ppcart_download_debug_log` and query argument `ppcart_download_debug_log_nonce`, and `wp_die()` is never called. The nonce is verified prior to streaming any file contents.

## Edge cases

- The download nonce action/query-arg must be distinct from the view nonce, so a view nonce cannot be replayed to authorize a file download.
