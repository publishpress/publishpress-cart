# Lost-password form verifies nonce before retrieve_password

## Scenario

The account lost-password form must include a Cart nonce and `do_password_lost()`
must reject POSTs without a valid `ppcart_lost_password` nonce before calling
`retrieve_password()`.

## Steps

1. POST to `do_password_lost()` without `ppcart_lost_password_nonce`.
2. POST with a valid nonce value accepted by verification.
3. Render the lost-password branch of the login form template.

## Expected result

1. Redirect includes `errors=lost_password_invalid_nonce` and `retrieve_password()`
   is not called.
2. `retrieve_password()` runs once and redirect includes `checkemail=confirm`.
3. Markup includes a hidden `ppcart_lost_password_nonce` field.

## Edge cases

- Default WordPress login flow is unchanged when `ppcart_use_default_authentication_logic`
  is true.
