# Autoloaded-options filter decrypts sensitive keys and leaves others untouched

## Scenario

Security case. WordPress loads autoloaded options in bulk via the `alloptions` cache, bypassing the per-option `get_option` decryption path. The `filter_alloptions_decrypt()` hook must decrypt only the sensitive, encrypted entries in that bundle (so integrations read usable credentials) while leaving non-sensitive options exactly as they are.

## Steps

1. Skip if OpenSSL is unavailable.
2. Encrypt the plaintext `ac-secret-key-value` with `encrypt_value()`.
3. Call `PPCart_Secrets::filter_alloptions_decrypt()` with a map containing the encrypted `_sc_activecampaign_secret_key` and a plain `_sc_currency` = `USD`.
4. Inspect both entries in the returned map.

## Expected result

- `_sc_activecampaign_secret_key` is decrypted to `ac-secret-key-value` in the returned bundle.
- `_sc_currency` remains `USD`, unchanged (non-sensitive options are never altered).

## Edge cases

- A sensitive key that is already plaintext in the bundle passes through unchanged; only encrypted sensitive values are decrypted.
