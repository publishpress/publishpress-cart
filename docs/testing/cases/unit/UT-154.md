# Manual migration encrypts existing plaintext credentials at rest

## Scenario

Security case. When an admin enables encryption on a site that already has plaintext credentials in `wp_options`, the manual migration routine must locate those plaintext secrets and rewrite them as ciphertext, reporting how many were migrated. This case migrates an existing plaintext Stripe secret key with encryption enabled.

## Steps

1. Skip if OpenSSL is unavailable, and skip if the `PPCART_ENCRYPT_SECRETS` constant is defined.
2. Enable the database flag (`ENCRYPT_SECRETS_OPTION` = `'1'`).
3. Seed `_sc_stripe_test_sk` as plaintext `sk_test_plaintext_migration` in both the raw and decrypted option stores.
4. Call `PPCart_Secrets::migrate_plaintext_secrets()`.
5. Inspect the returned report and the raw stored value with `is_encrypted_value()`.

## Expected result

- The result is an array with `migrated` equal to `1` (one credential migrated).
- The raw stored value of `_sc_stripe_test_sk` is now encrypted (`is_encrypted_value()` returns `true`), so the plaintext no longer exists at rest.

## Edge cases

- If encryption is disabled the routine refuses to run and returns a WP_Error instead of migrating (covered by UT-155).
