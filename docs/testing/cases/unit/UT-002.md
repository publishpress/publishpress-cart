# Settings Page Query Is Recognized As A Plugin Admin Screen

## Scenario

The Cart settings page is reached at `wp-admin/...?page=ppcart-settings`. Even before a screen object exists, `PPCart_Admin_Screens::is_plugin_screen()` should recognize the request from the `page` query alone, because `ppcart-settings` is a known plugin page slug (`PAGE_SETTINGS`). This is what lets the plugin enqueue its admin UI on its own settings page.

## Steps

1. Reset the admin screen context with `$_GET['page'] = 'ppcart-settings'` and no screen object.
2. Call `PPCart_Admin_Screens::is_plugin_screen()`.

## Expected result

`is_plugin_screen()` returns `true`: the `page` slug `ppcart-settings` is in the known `PAGE_SLUGS` list, so the request is treated as a plugin admin screen.

## Edge cases

- Contrast with UT-001 (no `page`, returns `false`): the single difference is the presence of the known `ppcart-settings` slug, proving slug detection works without a `get_current_screen()` object.
