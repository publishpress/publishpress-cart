# Stripe Subscription Ids Are Not Mistaken For Local Subscription Ids

## Scenario

A message may mention a Stripe subscription id like `sub_1TWCmcCgxOWS1li105rAItSD`. The viewer's local `subscription_id` field is an integer for the plugin's own subscription post id and must not be polluted by Stripe's alphanumeric id. This case verifies the parser keeps the local `subscription_id` neutral.

## Steps

1. Call `PPCart_Debug_Log_Viewer::parse_line()` with `[05/12/2026 6:32 AM] - SUCCESS : Stripe subscription created - ID sub_1TWCmcCgxOWS1li105rAItSD`.
2. Inspect the `subscription_id` field of the returned parsed entry.

## Expected result

- The parsed entry's `subscription_id` is `0`; the Stripe `sub_...` token is not coerced into the local subscription id.

## Edge cases

- A message containing both a Stripe `sub_...` id and a real local `#<number>` subscription reference should only populate the local id from the numeric reference.
