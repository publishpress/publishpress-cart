# Standalone Stripe Webhook Log Route Is A Plugin Admin Request

## Scenario

The Stripe webhook log viewer is reached via a standalone request flag `sc_view_stripe_webhook_log=1` rather than a registered admin page, and it fires without a screen object. `PPCart_Admin_Screens::is_plugin_screen()` must detect this route param so the log viewer is treated as a Cart admin request.

## Steps

1. Reset the admin screen context with the request flag `sc_view_stripe_webhook_log = 1` (present in `$_POST`/`$_REQUEST`) and no screen object.
2. Call `PPCart_Admin_Screens::is_plugin_screen()`.

## Expected result

`is_plugin_screen()` returns `true`: `sc_view_stripe_webhook_log` is one of the recognized `STANDALONE_ROUTE_PARAMS`, so the populated route params mark the request as a plugin admin screen.

## Edge cases

- Covers the route-param detection branch (no `page`, no hook, no screen); UT-018 asserts the same context via the dedicated `is_standalone_log_viewer_route()` check.
