# Detection Re-Reads The Current Screen On Every Call

## Scenario

The current screen object becomes available later in the admin request lifecycle. Detection must not cache a stale "no screen" answer: after `set_current_screen()` populates a Cart screen, a subsequent `PPCart_Admin_Screens::is_plugin_screen()` call must reflect the new screen. This case proves the helper recomputes context each call.

## Steps

1. Reset the admin screen context with empty query and no screen object, then call `PPCart_Admin_Screens::is_plugin_screen()`.
2. Set the current screen state to `{ id: 'ppcart_page_ppcart-settings', base: 'ppcart_page_ppcart-settings' }`.
3. Call `PPCart_Admin_Screens::is_plugin_screen()` again.

## Expected result

The first call returns `false` (no screen, no signals); the second call returns `true` because the now-present screen id `ppcart_page_ppcart-settings` is a known Cart hook. The differing results confirm the context is re-read, not cached, between calls.

## Edge cases

- Distinct from the static-input cases: this verifies freshness/no-stale-cache behavior across a state change within one request.
