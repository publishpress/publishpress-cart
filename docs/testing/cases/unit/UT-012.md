# Explicit `post_type=ppcart_product` Query Is A Plugin Screen Without A Screen Object

## Scenario

On `edit.php`/`post-new.php` the request carries `?post_type=ppcart_product` before the screen object resolves. When no screen object exists yet, `PPCart_Admin_Screens::is_plugin_screen()` should fall back to the query `post_type` and recognize a known Cart post type, so list-table and editor assets load on time.

## Steps

1. Reset the admin screen context with `$_GET['post_type'] = 'ppcart_product'` and no screen object.
2. Call `PPCart_Admin_Screens::is_plugin_screen()`.

## Expected result

`is_plugin_screen()` returns `true`: with no screen object present, the helper checks the query `post_type`, finds `ppcart_product` in the known post types, and treats the request as a plugin screen.

## Edge cases

- Exercises the "no screen object → trust the `post_type` query" branch; UT-013 shows a leftover `sc_product` query alone is NOT enough once a conflicting real screen object exists.
