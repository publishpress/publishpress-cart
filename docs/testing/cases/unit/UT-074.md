# Rejects an external URL that does not map into the uploads root

## Scenario

Security case. Because the resolver accepts in-site uploads URLs (UT-070), it must reject URLs on any other host so it cannot be used to fetch or serve off-site content. `PPCart_Files::resolve_local_download_path()` only remaps URLs that match the configured uploads `baseurl`; anything else has no local equivalent inside `ppcart-uploads` and must be refused. This case supplies a URL on an unrelated, attacker-controlled host.

## Steps

1. Stub `wp_upload_dir()` with `baseurl` = `https://example.test/wp-content/uploads` (the only allowed URL prefix).
2. Call `PPCart_Files::resolve_local_download_path('https://evil.example/secret.txt')`.

## Expected result

The validator finds no mapping into the allowed uploads root for the foreign host and returns `false`. No remote fetch is attempted and no local path is produced; the external URL is never served.

## Edge cases

- The host differs entirely from the site `baseurl`; a URL that merely shares a path suffix but lives on a different domain still fails the prefix match and is rejected.
