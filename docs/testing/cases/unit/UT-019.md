# Canonical `ppcart_page_` Submenu Hook Passed As Argument Is Recognized

## Scenario

When a hook suffix is supplied directly (as WordPress does on admin asset hooks), an unknown canonical-prefixed submenu hook like `ppcart_page_ppcart-future` must still be accepted. `PPCart_Admin_Screens::is_plugin_screen($hook_suffix)` matches it through the `ppcart_page_` prefix even with no screen object or query.

## Steps

1. Reset the admin screen context with empty query and no screen object.
2. Call `PPCart_Admin_Screens::is_plugin_screen('ppcart_page_ppcart-future')`, passing the hook suffix argument.

## Expected result

`is_plugin_screen()` returns `true`: the passed hook suffix begins with the `ppcart_page_` (`MENU_HOOK_PREFIX`) canonical prefix, so it is recognized as a plugin screen.

## Edge cases

- Like UT-010 (screen-id prefix) but exercising the explicitly passed hook-suffix path, confirming forward compatibility through the hook argument too.
