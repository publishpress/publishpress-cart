# One-Time Payment Plan Option ID Is Preserved

## Scenario

Each payment plan carries a stable `option_id` that other features reference. The one-time plan's identifier must survive duplication unchanged. This verifies the first `_sc_pay_options` row keeps its `option_id`.

## Steps

1. Seed the source with a first plan row whose `option_id` is `'plan_one'`.
2. Duplicate it.
3. Read `_sc_pay_options[0]['option_id']` from the duplicate.

## Expected result

`_sc_pay_options[0]['option_id']` equals `'plan_one'`, preserved exactly on the copy.

## Edge cases

- `option_id` is a local plan identity (preserved), unlike `stripe_plan_id` which is an external identity (cleared, UT-113).
