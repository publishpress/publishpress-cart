# Contacts Page Is Covered By The Order/Contact/Customer-Report UI Asset Group

## Scenario

Several admin surfaces (Cart product/order/subscription editors, the contacts page, and customer reports) share one UI asset bundle. `PPCart_Admin_Screens::is_order_contact_or_customer_report_screen()` is the grouping check that decides whether to load those shared assets. The contacts page at `?page=ppcart-contacts` must be part of that group.

## Steps

1. Reset the admin screen context with `$_GET['page'] = 'ppcart-contacts'` and no screen object.
2. Call `PPCart_Admin_Screens::is_order_contact_or_customer_report_screen()`.

## Expected result

`is_order_contact_or_customer_report_screen()` returns `true`: the `page` slug `ppcart-contacts` matches the contacts page (`PAGE_CONTACTS`), which is one of the members of this shared asset group, so the contacts page qualifies.

## Edge cases

- Canonical `ppcart_product` / `ppcart_order` editors are in the same asset groups after step 1.
