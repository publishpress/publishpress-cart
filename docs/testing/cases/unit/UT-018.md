# Standalone Log Viewer Route Is Exposed By A Dedicated Check

## Scenario

Callers need to distinguish a standalone log-viewer request from ordinary plugin screens (it renders its own minimal page rather than the admin shell). `PPCart_Admin_Screens::is_standalone_log_viewer_route()` provides that explicit signal by reporting whether any standalone route param is present.

## Steps

1. Reset the admin screen context with the request flag `sc_view_stripe_webhook_log = 1` and no screen object.
2. Call `PPCart_Admin_Screens::is_standalone_log_viewer_route()`.

## Expected result

`is_standalone_log_viewer_route()` returns `true`: the request carries the `sc_view_stripe_webhook_log` route param, so the dedicated standalone-route check reports the log viewer route.

## Edge cases

- Pairs with UT-017 (broad `is_plugin_screen`) to confirm the same route also has a narrow, purpose-built accessor for the standalone log page.
