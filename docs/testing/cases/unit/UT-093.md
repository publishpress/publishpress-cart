# Legacy Indexed Refund Logs Are Summed

## Scenario

Older orders store `_sc_refund_log` as a plain numerically indexed array of refund entries rather than a map keyed by refund ID. `PPCart_Order_Refunds::get_refund_total()` must still sum every entry's `amount` so the refund total reflects multiple legacy refunds. This confirms the summation works for the legacy indexed shape with no stored `_sc_refund_amount`.

## Steps

1. Seed order `668` post meta with `_sc_amount = "200.00"` and `_sc_refund_log` as an indexed array of two entries: `re_one` with `amount = "25.00"` and `re_two` with `amount = "50.00"` (no `_sc_refund_amount` set).
2. Call `PPCart_Order_Refunds::get_refund_total(668)`.
3. The method sums the log entries (25.00 + 50.00) and compares against the absent stored amount (parses to 0), returning the larger.

## Expected result

The computed refund total is exactly `75.0` (float), the sum of the two legacy entries.

## Edge cases

- Entries lacking an `amount` key are skipped rather than treated as zero-causing errors.
- Negative entry amounts are summed by absolute value so they still increase the refund total.
