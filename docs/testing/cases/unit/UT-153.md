# Pre-update hook blocks secret changes without manage_options

## Scenario

Security case. Changing a stored credential is a privileged action, so the `pre_update_option` filter must verify the current user holds the `manage_options` capability. When the capability is absent, an attempted change to a sensitive option must be rejected and the previously stored value retained, preventing privilege escalation or credential tampering by an under-privileged user.

## Steps

1. Set the current user's `manage_options` capability to absent (`canManageOptions = false`).
2. Define the existing stored value `old = 'sk_test_existing'`.
3. Call `PPCart_Secrets::filter_pre_update_any_option('sk_test_changed', '_sc_stripe_test_sk', $old)` (attempted new value, key, old value).
4. Compare the returned value to the old value.

## Expected result

- The returned value equals `sk_test_existing` (the old value): the attempted change to `sk_test_changed` is blocked because the user lacks `manage_options`.

## Edge cases

- With `manage_options` present, the same call proceeds and (when the flag is on) encrypts the new value; the capability check is the gate that distinguishes the two outcomes.
