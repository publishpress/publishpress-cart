# Checkout reference binds the customer to one visitor, mode, and intent

## Scenario

The browser gets an opaque checkout reference instead of a Stripe customer ID.
The server maps the reference to the customer.

## Steps

1. Create a reference for `cus_guest` and `pi_123`.
2. Read it in `test` and `live` mode, and read a posted customer ID or unknown value.
3. Resolve the order customer with the same and with another intent.
4. Read the reference as another WordPress user.

## Expected result

1. The reference is 64 hex characters.
2. Only the same mode returns the customer. Customer IDs and unknown values return nothing.
3. Only the same intent returns the customer.
4. Another user gets nothing.

## Edge cases

- A reference for an invalid customer ID is not created.
