# Profile AJAX rejects updates when edit_user capability fails

## Scenario

`ppcart_update_user_profile()` verifies login and a Cart AJAX nonce, then must require `edit_user` on the current user before parsing form data or calling `wp_update_user()`.

## Steps

1. Stub a logged-in user with a valid nonce.
2. Stub `current_user_can( 'edit_user', … )` to return false.
3. Invoke `ppcart_update_user_profile()`.

## Expected result

The handler returns a JSON error and does not call `wp_update_user()` or `wp_set_password()`.

## Edge cases

- Capability failure happens before form validation so empty `form_data` still denies safely.
