# Allows an uploads URL that maps to a real ppcart-uploads file

## Scenario

Security case. Stored download targets are sometimes recorded as public URLs rather than filesystem paths, so `PPCart_Files::resolve_local_download_path()` must accept a site `baseurl` upload URL and translate it back into the allowed local file. This case proves that a URL under the site's own uploads base, pointing at a real file inside `ppcart-uploads`, is accepted and resolved to the on-disk path. Only URLs that map into the allowed uploads root may be served (external URLs are rejected in UT-074).

## Steps

1. Stub `wp_upload_dir()` with `basedir` = temp `wp-content/uploads` and `baseurl` = `https://example.test/wp-content/uploads`.
2. Ensure the real file `<ppcart-uploads>/product.zip` exists.
3. Call `PPCart_Files::resolve_local_download_path('https://example.test/wp-content/uploads/ppcart-uploads/product.zip')`.

## Expected result

The validator maps the uploads URL to its local file and returns the resolved canonical path `realpath('<ppcart-uploads>/product.zip')` (a non-empty string), not `false`. The URL is treated as an allowed in-site reference and converted to the safe local path for streaming.

## Edge cases

- The URL must match the configured `baseurl` prefix to be remapped; a URL on a different host (even if visually similar) does not resolve into the allowed root and is rejected.
