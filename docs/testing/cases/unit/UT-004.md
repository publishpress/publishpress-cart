# Settings Hook Suffix Is Detected From The Passed Hook Alone

## Scenario

During early admin hooks (e.g. `admin_enqueue_scripts`), WordPress passes the current hook suffix as an argument before a screen object exists. `PPCart_Admin_Screens::is_settings_screen()` must recognize the settings screen from that hook suffix string `ppcart_page_ppcart-settings` (`HOOK_SETTINGS`) even when `get_current_screen()` is `null` and `$_GET['page']` is absent.

## Steps

1. Reset the admin screen context with empty query and no screen object.
2. Call `PPCart_Admin_Screens::is_settings_screen('ppcart_page_ppcart-settings')`, passing the hook suffix explicitly.

## Expected result

`is_settings_screen()` returns `true`: the passed hook suffix equals the expected settings hook `ppcart_page_ppcart-settings`, so it is detected as the settings screen without any screen object or `page` query.

## Edge cases

- Covers the hook-suffix branch (vs UT-003's `page`-query branch); important for callbacks that fire before `current_screen` is populated.
