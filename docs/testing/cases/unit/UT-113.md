# Recurring Stripe Price ID Is Cleared On Duplicate

## Scenario

A Stripe price ID is an external identity tied to one specific product/price, not local config. Reusing it on a copy would make the duplicate point at the source's Stripe object. This verifies the recurring plan's `stripe_plan_id` is emptied on the duplicate so its next save creates its own Stripe price.

## Steps

1. Seed the source recurring plan with `stripe_plan_id` `'price_source_recurring'`.
2. Duplicate it (`prepare_meta_value_for_duplicate` clears Stripe ids on `_sc_pay_options`).
3. Read `_sc_pay_options[1]['stripe_plan_id']` from the duplicate.

## Expected result

`_sc_pay_options[1]['stripe_plan_id']` is an empty string `''`; the source value is deliberately discarded on the copy.

## Edge cases

- Cleared, not copied and not removed: the field still exists but is blank, while the row and its `option_id` are preserved (UT-110/UT-112). Distinct from `sale_stripe_plan_id`, which is cleared separately (UT-114).
