# Re-Running Registration Does Not Duplicate Existing Core Option Filters

## Scenario

Because registration runs both at file load and again on `init` (priority `99`), `ppcart_register_email_template_option_filters()` must be idempotent for already-registered options. It guards each option with a static `$registered` map and skips any option already wired. This case verifies that re-running the registrar does not add a second callback to a core option's `default_option_*` hook.

## Steps

1. After file-load registration, record the callback count for `default_option__ppcart_email_completed_subject`.
2. Call `ppcart_register_email_template_option_filters()` a second time.
3. Re-count callbacks on `default_option__ppcart_email_completed_subject`.

## Expected result

- The callback count is unchanged between the two reads (still `1`): the static `$registered` guard prevents a duplicate `add_filter` for an already-registered core option.

## Edge cases

- Idempotency matters because the file-load pass and the `init` priority-`99` pass both call the same registrar; without the guard, every core option would accumulate duplicate filters.
