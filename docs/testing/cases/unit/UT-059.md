# Flow Group Timeline Reads Oldest To Newest

## Scenario

Within a single flow group, entries form a timeline that should read in chronological order so admins can follow the request step by step. This case verifies the first entry in the group is the earliest event.

## Steps

1. Log a validation-started event followed by an order-saved event under `flow_id` `unit-checkout-1`.
2. Build groups via `group_entries()` and select the `flow:unit-checkout-1` group.
3. Inspect `entries[0]['message']` of that group.

## Expected result

- The group's first timeline entry message is `Checkout form validation started.`, i.e. the oldest event appears first.

## Edge cases

- Entries written out of order by sequence must still be ordered oldest-to-newest inside the group.
