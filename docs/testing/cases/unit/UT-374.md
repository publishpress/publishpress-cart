# Embed frame headers keep the site's other Content-Security-Policy rules

## Scenario

A security plugin may already send a Content-Security-Policy with rules such as
`script-src` and `frame-ancestors`. PHP `header()` replaces a header of the same
name, so the embed must not send one line that wipes those rules. It keeps every
existing policy without its `frame-ancestors` directive and adds its own.

## Steps

1. Build the header lines for sources `*` with three existing policies: one with
   `script-src`, `frame-ancestors` and `object-src`, one with only an upper-case
   `FRAME-ANCESTORS`, and one with `upgrade-insecure-requests;`.

## Expected result

Three lines: the first policy without `frame-ancestors`, the
`upgrade-insecure-requests` policy, and `frame-ancestors *`. The policy that
held only `frame-ancestors` is dropped.

## Edge cases

- Directive names match in any letter case.
- An empty directive from a trailing semicolon is dropped.
