# Credit note refund id is resolved through Stripe

## Scenario

A credit note created with a refund returns a refund id, but the flow re-fetches that refund from Stripe to obtain the authoritative refund object before syncing it locally. This test confirms the refund is retrieved exactly once through the Stripe `refunds` service.

## Steps

1. Build a Stripe client stub whose `creditNotes->create()` returns `{ id: 'cn_test', refund: 're_test' }`, and whose `refunds->retrieve()` counts its calls.
2. Call `ppcart_issue_stripe_subscription_cancellation_refund()` with order `{ id: 321, subscription_id: 'sub_test' }` and subscription `{ id: 'sub_test', latest_invoice: 'in_test' }` (invoice `in_test`, `amount_paid = 2000`, `post_payment_credit_notes_amount = 500`).
3. Inspect the stub's `refunds->retrieve_count`.

## Expected result

The refund `re_test` from the credit note is fetched through Stripe, so `refunds->retrieve_count` equals `1`.

## Edge cases

- The refund id comes from the credit note's `refund` field (`re_test`); the function relies on Stripe's returned refund rather than fabricating a local one.
