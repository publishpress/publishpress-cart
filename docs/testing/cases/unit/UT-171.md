# Credit note targets the subscription's latest invoice

## Scenario

The credit note must be attached to the correct invoice — the subscription's most recent paid invoice — otherwise Stripe would credit the wrong charge. This test confirms the `invoice` argument sent to `creditNotes->create()` is the subscription's `latest_invoice` id.

## Steps

1. Build a Stripe client stub whose latest invoice is `in_test` (`amount_paid = 2000`, `post_payment_credit_notes_amount = 500`).
2. Call `ppcart_issue_stripe_subscription_cancellation_refund()` with order `{ id: 321, subscription_id: 'sub_test' }` and subscription `{ id: 'sub_test', latest_invoice: 'in_test' }`.
3. Read `creditNotes->last_args['invoice']` captured by the stub.

## Expected result

The credit note is created against `invoice = 'in_test'`, the subscription's latest invoice.

## Edge cases

- The target invoice id comes from the resolved Stripe subscription's `latest_invoice`, so changing the subscription's latest invoice would redirect the credit note accordingly.
