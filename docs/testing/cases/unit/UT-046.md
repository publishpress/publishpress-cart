# Structured Context Exposes Safe Stripe Ids

## Scenario

Not all Stripe values are sensitive. Non-secret identifiers like a charge id (`ch_...`) are useful for support and should be surfaced in a dedicated `stripe_ids` list. This case verifies a charge id from structured context is exposed, in contrast to redacted secrets.

## Steps

1. Call `PPCart_Debug_Log_Viewer::parse_line()` with `[05/12/2026 6:32 AM] - STATUS : Stripe PaymentIntent created successfully. context={"event":"checkout.payment_intent.created","order_id":627,"client_secret":"pi_secret","charge_id":"ch_123"}`.
2. Inspect the `stripe_ids` array in the returned parsed entry.

## Expected result

- The `stripe_ids` array contains `ch_123`, making the safe charge id visible while `client_secret` stays redacted.

## Edge cases

- Multiple safe Stripe ids in one context (e.g. charge and payment intent) should all be collected into `stripe_ids`.
