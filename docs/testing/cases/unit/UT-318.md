# Product header background color survives checkout stylesheet cascade

## Scenario

The product field Header Background Color (`_ppcart_header_color`) is painted
on `.ppcart-hero-banner`. `ppcart-public.css` sets that class with the
`background` shorthand. Checkout1 used to enqueue the product CSS before
`wp_enqueue_scripts`, so the fallback handle printed first and the stylesheet
reset the color to `#234854`.

## Steps

1. Call `ppcart_enqueue_or_print_inline_style()` before `wp_enqueue_scripts`.
2. Assert the CSS is deferred onto `wp_enqueue_scripts` and
   `admin_enqueue_scripts` at priority 20, not attached immediately.
3. Invoke the deferred `wp_enqueue_scripts` callback and assert the CSS is
   attached to the `ppcart` handle via `wp_add_inline_style`.
4. Call it again after `wp_enqueue_scripts` with a registered `ppcart` handle
   and assert the same attach path.

## Expected result

Early checkout CSS waits until the `ppcart` handle exists, then attaches to
that handle so the stylesheet shorthand cannot win.

## Edge cases

- Shortcode checkout after `wp_head()` still uses the late fallback print path.
