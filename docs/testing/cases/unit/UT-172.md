# Credit note carries the local subscription id in metadata

## Scenario

So the credit note can be traced back to the originating local record, the cancellation refund attaches the local subscription/order id as Stripe metadata under `ppcart_subscription_id`. This test confirms the local id is stamped onto the credit note's `metadata`.

## Steps

1. Build a Stripe client stub whose latest invoice `in_test` has `amount_paid = 2000` and `post_payment_credit_notes_amount = 500`.
2. Call `ppcart_issue_stripe_subscription_cancellation_refund()` with local order `{ id: 321, subscription_id: 'sub_test' }` and subscription `{ id: 'sub_test', latest_invoice: 'in_test' }`.
3. Read `creditNotes->last_args['metadata']['ppcart_subscription_id']` captured by the stub.

## Expected result

The credit-note metadata includes `ppcart_subscription_id = '321'` (the local order id, as a string).

## Edge cases

- The metadata value is the local record id (`321`), not the Stripe subscription id (`sub_test`), preserving the link to WordPress data.
