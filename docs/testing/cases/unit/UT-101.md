# Duplicate Returns A New Post ID, Not An Error

## Scenario

Duplicating a valid `ppcart_product` should succeed and hand back the new post ID. This verifies the happy-path return contract of `PPCart_Product_Duplicator::duplicate()` so callers can rely on a usable ID rather than a failure object.

## Steps

1. Seed a valid source product (post type `ppcart_product`, ID 101) with its full meta/term fixture.
2. Call `PPCart_Product_Duplicator::duplicate($sourceId)`.
3. Pass the return value through `is_wp_error()`.

## Expected result

`is_wp_error($duplicate_id)` is `false`. `duplicate()` only returns a `WP_Error` for an invalid/non-`ppcart_product` source; a valid product yields the inserted post ID.

## Edge cases

- The error branch (`invalid_product`) is not exercised here; this is the positive contract that a real product never returns `WP_Error`.
