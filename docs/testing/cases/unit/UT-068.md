# Debug Log Reset Keeps Reset Marker As Latest Entry

## Scenario

After a reset, the log should not be empty: it should contain a single marker entry indicating the reset happened, so admins know the log was intentionally cleared. This case verifies the post-reset log holds exactly one entry whose message identifies the reset.

## Steps

1. Instantiate `PPCart_Debug_Logger` and write 8 padded rows (forcing rotation).
2. Call `reset_log_file()`.
3. Call `PPCart_Debug_Log_Viewer::read_entries(['limit' => 10])` and inspect the entries.

## Expected result

- Exactly one entry remains, and its `message` contains `Log File Reset`, serving as the latest marker.

## Edge cases

- A reset on an already-empty log should still leave just the single reset-marker entry, not zero entries.
