# Debug Log Groups Are Sorted Newest First

## Scenario

While entries inside a group read oldest-to-newest, the groups themselves should be listed newest-first so the most recent activity appears at the top of the viewer. This case verifies the most recently active flow group sorts ahead of an earlier one.

## Steps

1. Log events for `flow_id` `unit-checkout-1` first, then a later event for `flow_id` `unit-checkout-2`.
2. Build the grouped list via `group_entries()`.
3. Inspect `groups[0]['key']`.

## Expected result

- The first group's `key` is `flow:unit-checkout-2`, the most recently active flow, confirming newest-first group ordering.

## Edge cases

- Groups whose latest events share a timestamp should still sort deterministically.
