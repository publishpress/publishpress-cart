# Order post statuses map to ppcart_ registered slugs

## Scenario

WordPress.org requires plugin-registered post statuses to use a unique prefix.
Cart keeps logical status strings (`paid`, `pending-payment`) on order meta and
`$order->status`. `PPCart_Status_Labels` maps those onto `ppcart_*` slugs for
`register_post_status()` and `wp_posts.post_status`. `pending-payment` becomes
`ppcart_pending` so the slug fits the varchar(20) column.

## Steps

1. Call `registered_slug`, `logical_slug`, and `query_slugs` for `paid` and `pending-payment`.
2. Measure every mapped registered slug length.
3. Register a WordPress status object for `ppcart_paid` and call `get('paid')`.
4. Call `edit_select_value` for `ppcart_paid` and `ppcart_pending`.
5. Run `map_insert_post_data` for a canonical order (`paid`), a leftover `sc_order` (`paid`), and `publish`.
6. Expand a `paid` query status and an `any` status.

## Expected result

- `paid` ↔ `ppcart_paid`; `pending-payment` ↔ `ppcart_pending`.
- Query slugs include both prefixed and logical values.
- Every registered slug is 20 characters or fewer.
- `get('paid')` returns the prefixed object's label.
- Select values stay logical (`paid`, `pending`).
- Canonical order writes become `ppcart_paid`. Leftover `sc_order` and `publish` are unchanged.
- `paid` expands to both slugs; `any` is unchanged.

## Edge cases

- Unknown statuses pass through unmapped.
- `initiated` is not a registered post status and stays logical.
