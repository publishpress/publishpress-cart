# get_decrypted_option leaves plaintext untouched when encryption is off

## Scenario

Security case. Lazy migration on read must be strictly gated on the encryption flag. When encryption is disabled, reading a plaintext sensitive option through `get_decrypted_option()` must return the value as-is and must not encrypt it, so the plugin never produces ciphertext the admin has not opted into and cannot guarantee it can decrypt.

## Steps

1. Skip if OpenSSL is unavailable, and skip if the `PPCART_ENCRYPT_SECRETS` constant is defined.
2. Disable the database flag (remove `ENCRYPT_SECRETS_OPTION`).
3. Seed `_sc_stripe_test_sk` as plaintext `sk_test_stays_plain_on_read` in both raw and decrypted stores.
4. Call `PPCart_Secrets::get_decrypted_option('_sc_stripe_test_sk')` and inspect the raw stored value afterward.

## Expected result

- The call returns the plaintext `sk_test_stays_plain_on_read`.
- The raw stored value of `_sc_stripe_test_sk` remains plaintext (`is_encrypted_value()` returns `false`): no lazy migration occurs while encryption is off.

## Edge cases

- The mirror of UT-160: the encryption flag is the single switch that decides whether a read upgrades stored plaintext to ciphertext.
