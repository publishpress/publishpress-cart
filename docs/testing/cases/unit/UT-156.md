# Plaintext-credential detector flags unencrypted secrets and builds the admin notice

## Scenario

Security case. Before nudging admins to migrate, the plugin must accurately detect whether any sensitive option is still stored as plaintext in `wp_options`, count them, and surface a clear notice. This case verifies detection flips from clean to dirty when a plaintext Stripe secret appears, and that the migration status and notice reflect it.

## Steps

1. Skip if the `PPCART_ENCRYPT_SECRETS` constant is defined; disable the database flag.
2. Call `PPCart_Secrets::has_plaintext_stored_credentials()` with no plaintext secrets present.
3. Seed the raw store with plaintext `_ppcart_stripe_test_sk` = `sk_test_plaintext`.
4. Call `has_plaintext_stored_credentials()` again, then `get_migration_status()`, then `get_plaintext_migration_notice($status)`.

## Expected result

- First check returns `false` (no plaintext secrets).
- After seeding, the check returns `true`.
- `get_migration_status()` reports `plaintext_count` of `1` and `has_plaintext_secrets` of `true`.
- The migration notice text contains `encrypt it automatically`, prompting the admin to migrate.

## Edge cases

- An already-encrypted value in the same key must not be counted as plaintext; only raw, unencrypted credential values increment `plaintext_count`.
