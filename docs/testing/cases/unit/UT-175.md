# Credit note refund is synced into the local record

## Scenario

After Stripe issues the refund tied to the credit note, the refund must be recorded locally so the subscription/order reflects it. This test confirms the resolved refund id is passed into `PPCart_Stripe_Sync` for local synchronization.

## Steps

1. Reset `PPCart_Stripe_Sync::$synced_refund_ids` to an empty array.
2. Build a Stripe client stub whose credit note returns refund `re_test` (invoice `in_test`, `amount_paid = 2000`, `post_payment_credit_notes_amount = 500`).
3. Call `ppcart_issue_stripe_subscription_cancellation_refund()` with order `{ id: 321, subscription_id: 'sub_test' }` and subscription `{ id: 'sub_test', latest_invoice: 'in_test' }`.
4. Inspect `PPCart_Stripe_Sync::$synced_refund_ids`.

## Expected result

The synced refund ids equal `['re_test']`, confirming the credit note's refund was handed to the local sync layer exactly once.

## Edge cases

- Exactly the Stripe-resolved refund id (`re_test`) is synced; no duplicate or placeholder refund id is recorded.
