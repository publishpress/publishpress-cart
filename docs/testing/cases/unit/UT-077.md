# Honors an additional allowed root registered via the filter

## Scenario

Security case. Extensions may legitimately store downloadable files outside the default `ppcart-uploads` directory, so `PPCart_Files::resolve_local_download_path()` consults the `ppcart_download_allowed_roots` filter to learn extra trusted roots. This case proves the allow-list is extensible but still strict: a file outside `ppcart-uploads` is accepted only because its containing directory was explicitly added to the allowed roots via the filter. Without that registration, the same path would be rejected like any other out-of-root location.

## Steps

1. Stub `wp_upload_dir()` so the default allowed root is the temp `wp-content/uploads/ppcart-uploads`.
2. Create a separate directory `<tempRoot>/extra-downloads` (outside `ppcart-uploads`) containing a real `bonus.zip`.
3. Hook `apply_filters('ppcart_download_allowed_roots', ...)` to append `realpath('<tempRoot>/extra-downloads')` to the allowed roots.
4. Call `PPCart_Files::resolve_local_download_path('<tempRoot>/extra-downloads/bonus.zip')`.

## Expected result

The validator treats the filtered directory as an allowed root, accepts the file, and returns its resolved canonical path `realpath('<tempRoot>/extra-downloads/bonus.zip')` (not `false`). Access is granted strictly because the root was explicitly allow-listed.

## Edge cases

- If the filter did not append the extra root, this same out-of-`ppcart-uploads` path would be rejected, confirming the filter widens access only for explicitly trusted directories.
- Leftover `sc-uploads` is not registered by Cart; Compat adds it via this filter while Compatibility Mode is on (IT-361).
