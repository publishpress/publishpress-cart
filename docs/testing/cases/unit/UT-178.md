# Refund-failure response keeps cancellation success and URL-encodes the message

## Scenario

A subscription can cancel successfully even if the follow-up refund fails. In that case the response still signals success but appends the failure reason, URL-encoded (not HTML-entity-encoded) so apostrophes and spaces survive transport to the frontend intact. This test confirms the response format and that the message is `rawurlencode`-style escaped rather than mangled into HTML entities.

## Steps

1. Call `ppcart_get_subscription_cancel_success_response("Couldn't process refund")`.
2. Compare the return value to the expected encoded string.

## Expected result

The function returns `OK_REFUND_FAILED|Couldn%27t%20process%20refund` — the success token, a `|` separator, and the URL-encoded message (`'` → `%27`, space → `%20`).

## Edge cases

- The apostrophe is encoded as `%27`, not as the HTML entity `&#039;` / `&apos;`, ensuring the message is not double-escaped or corrupted when the frontend decodes it.
