# Public-page proof accepts owner, token, or manage_options

## Scenario

`PPCart_Order::visitor_can_view()` is the public-page proof for confirmation pages, `[ppcart_order_downloads]`, and `[ppcart_order_detail]`. A stranger with only an order ID is denied. A guest with the Order access token, the logged-in owner, or `manage_options` is allowed. A parent token does not unlock a child order ID. `confirmation_url()` appends `ppcart-order` and `token`.

## Steps

1. Stub order meta and the current user.
2. Call `visitor_can_view()` and `confirmation_url()`.

## Expected result

Denied without proof. Allowed for token, owner, or admin. Child ID stays denied when only the parent token is present. Confirmation URL includes both query args.

## Edge cases

- Empty stored token and empty request token must not `hash_equals` as a match.
- Guest orders have `user_account` 0; owner match requires both ids to be non-zero.
