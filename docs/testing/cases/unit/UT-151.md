# Pre-update hook stores plaintext when the database flag is off

## Scenario

Security case. Encryption must be strictly opt-in: when the database flag is off, the `pre_update_option` filter must not encrypt the sensitive option and must store the value exactly as submitted. This prevents the plugin from producing ciphertext the site cannot later decrypt (e.g. if the encryption key is unavailable) and keeps behavior predictable when the admin has not opted in.

## Steps

1. Skip if OpenSSL is unavailable, and skip if the `PPCART_ENCRYPT_SECRETS` constant is defined.
2. Disable the database flag (remove `ENCRYPT_SECRETS_OPTION`).
3. Call `PPCart_Secrets::filter_pre_update_any_option('sk_test_plain_when_disabled', '_sc_stripe_test_sk', '')`.
4. Compare the returned value to the submitted plaintext and check `is_encrypted_value()`.

## Expected result

- The returned value equals the original `sk_test_plain_when_disabled` (unchanged).
- `is_encrypted_value()` returns `false`, confirming `_sc_stripe_test_sk` is stored as plaintext while encryption is off.

## Edge cases

- The same key is encrypted on write only when the flag is on (UT-150); toggling the flag is the single switch that governs encrypt-vs-plaintext storage.
