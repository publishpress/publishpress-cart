# Partial Refund Total Is Read From Refund Metadata

## Scenario

`PPCart_Order_Refunds::get_refund_total()` reports how much of an order has been refunded by reading the order's refund metadata. For a $200.00 order that was partially refunded by $100.00, the calculator combines the keyed `_sc_refund_log` entry and the stored `_sc_refund_amount` and returns the larger of the two as the refund total. This confirms the refund total is sourced from refund metadata rather than recomputed elsewhere.

## Steps

1. Seed order `667` post meta with `_sc_amount = "200.00"`, `_sc_refund_amount = "100.00"`, and `_sc_refund_log` holding one entry keyed `re_partial` with `amount = "100.00"`.
2. Call `PPCart_Order_Refunds::get_refund_total(667)`.
3. The method sums the log (100.00) and parses the stored refund amount (100.00), then returns `max(0, max(log, stored))`.

## Expected result

The computed refund total is exactly `100.0` (float), matching both the summed log entry and the stored refund amount.

## Edge cases

- When the summed log and stored refund amount disagree, the larger value wins (covered separately); here both equal 100.00 so the result is unambiguous.
- A negative or missing stored amount must never pull the refund total below `0`.
