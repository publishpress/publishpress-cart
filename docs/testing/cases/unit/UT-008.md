# Core Dashboard Stays Excluded Even With A Cart Menu Parent

## Scenario

A misleading context can arise where the screen is the core `dashboard` yet `get_admin_page_parent()` resolves to `ppcart` (the Cart menu parent). The core-screen exclusion must still win: `PPCart_Admin_Screens::is_plugin_screen()` rejects a `dashboard` screen before the admin-parent fallback is ever considered, preventing false positives from a stray parent value.

## Steps

1. Reset the admin screen context with a screen object `{ id: 'dashboard', base: 'dashboard' }` and `admin_page_parent = 'ppcart'`.
2. Call `PPCart_Admin_Screens::is_plugin_screen()`.

## Expected result

`is_plugin_screen()` returns `false`: the excluded-core-screen check (`base`/`id` is `dashboard`) runs first and short-circuits, so the `ppcart` admin parent never promotes it to a plugin screen.

## Edge cases

- Boundary against the admin-parent fallback branch: confirms exclusion precedence — a Cart parent cannot rescue a core dashboard screen.
