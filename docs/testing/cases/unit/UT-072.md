# Rejects a `../` traversal that escapes the upload directory

## Scenario

Security case. Path traversal (`../`) is the primary way to break out of an allowed directory while starting from a legitimate-looking prefix. `PPCart_Files::resolve_local_download_path()` must canonicalize the path and reject anything that resolves outside the allowed `ppcart-uploads` root. This case feeds a path that begins inside `ppcart-uploads` but climbs out with `../../../` to reach `wp-config.php`.

## Steps

1. Stub `wp_upload_dir()` so the allowed root is the temp `wp-content/uploads/ppcart-uploads`.
2. Have a real `wp-config.php` sitting above the uploads directory.
3. Call `PPCart_Files::resolve_local_download_path('<ppcart-uploads>/../../../wp-config.php')`.

## Expected result

The validator normalizes the `../` segments, sees the canonical target lands outside `ppcart-uploads`, and returns `false`. The traversal does not yield the real config path; the file is never resolved or served.

## Edge cases

- The traversal resolves to a real, existing file, so rejection comes from the post-normalization boundary check rather than from the file being absent.
