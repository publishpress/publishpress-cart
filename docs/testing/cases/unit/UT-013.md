# Stale `post_type` Query Does Not Hijack An Unrelated WP-Admin Screen

## Scenario

A leftover `?post_type=sc_product` in the URL must not promote an unrelated screen (e.g. the Media Library, screen id `upload`) to a Cart screen. Once a real screen object exists, `PPCart_Admin_Screens` trusts the screen's own post type/id over the query string, so the stale query parameter is ignored.

## Steps

1. Reset the admin screen context with `$_GET['post_type'] = 'sc_product'` AND a screen object `{ id: 'upload', base: 'upload' }` (post type state blank).
2. Call `PPCart_Admin_Screens::is_plugin_screen()`.
3. Call `PPCart_Admin_Screens::is_post_type_screen('sc_product')`.

## Expected result

Both return `false`: with a screen object present the helper uses the screen's `post_type`/`current_post_type` (empty) and screen id `upload` (not a Cart hook/post type), so the dangling `post_type=sc_product` query does not make it a plugin or `sc_product` screen.

## Edge cases

- Boundary against UT-012: the query `post_type` only counts when there is no screen object; a concrete foreign screen overrides it.
