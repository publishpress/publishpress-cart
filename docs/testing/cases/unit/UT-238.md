# Report cron registration waits until init before translating

## Scenario

WordPress 6.7 JIT-loads the `publishpress-cart` text domain when a translation
function runs. That must not happen before `init`. The summary-report cron
schedules used to call `wp_next_scheduled()` while `schedule-event.php` was
included, which applied `cron_schedules` and translated labels too early.

## Steps

1. Load `includes/schedule-event.php` with stubbed `add_action` / `get_option`.
2. Confirm `ppcart_register_report_schedule_event` is hooked to `init`.
3. Confirm `ppcart_report_schedule` is not read at file load.
4. Call `ppcart_email_schedule_hook()` before `init` and assert `__()` is not
   invoked. After `init`, assert labels are translated.

## Expected result

Report cron registration is deferred to `init`. Schedule display strings stay
untranslated until `init` has run, so `_load_textdomain_just_in_time` is not
triggered too early for `publishpress-cart`.

## Edge cases

- `wp_get_schedules()` from another plugin before `init` still must not
  translate Cart labels.
