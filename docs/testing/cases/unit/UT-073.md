# Rejects a nested `../` traversal that escapes the upload directory

## Scenario

Security case. Traversal payloads often start from a deeper, valid-looking subdirectory to disguise the escape. `PPCart_Files::resolve_local_download_path()` must still canonicalize and reject any path whose resolved location falls outside the allowed `ppcart-uploads` root, regardless of how nested the starting point is. This case starts inside `ppcart-uploads/nested` and then climbs out with `../../../` to reach `wp-config.php`.

## Steps

1. Stub `wp_upload_dir()` so the allowed root is the temp `wp-content/uploads/ppcart-uploads`.
2. Ensure `<ppcart-uploads>/nested/` exists and a real `wp-config.php` sits above the uploads directory.
3. Call `PPCart_Files::resolve_local_download_path('<ppcart-uploads>/nested/../../../wp-config.php')`.

## Expected result

The validator resolves the nested `../` segments, determines the canonical target is outside `ppcart-uploads`, and returns `false`. The deeper starting directory does not bypass the boundary check; the config file is never resolved or served.

## Edge cases

- Compared with UT-072, the only difference is the deeper `nested/` starting point, confirming the boundary check is enforced on the final canonical path rather than on the input prefix.
