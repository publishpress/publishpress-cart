# Core Email Option Value Filter Is Registered During File Load

## Scenario

Beyond the default-resolution hook, `ppcart_register_email_template_option_filters()` also hooks the WordPress `option_<option>` filter for each core email option so a stored-but-empty value is upgraded to the template default. This case verifies that the value filter for the canonical "order complete" subject option `_ppcart_email_completed_subject` is attached exactly once during file-load registration.

## Steps

1. Load `ppcart-email-template-functions.php`, which calls `ppcart_register_email_template_option_filters()` at file scope.
2. For `_ppcart_email_completed_subject`, the registrar calls `add_filter('option__ppcart_email_completed_subject', 'ppcart_email_template_option_value', 10, 2)`.
3. Count the callbacks registered against the `option__ppcart_email_completed_subject` hook in the stub filter registry.

## Expected result

- The `option__ppcart_email_completed_subject` hook has exactly `1` registered callback (`ppcart_email_template_option_value`), at priority `10` accepting `2` args.

## Edge cases

- The `option_*` (value) filter is registered alongside, but is distinct from, the `default_option_*` filter; both must exist for the same option so empty stored values and missing values both resolve to the default.
