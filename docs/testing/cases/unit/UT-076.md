# Rejects an empty download path

## Scenario

Security case. Missing or blank stored download targets must never be coerced into a valid path (which could otherwise resolve to a directory root or the current working directory). `PPCart_Files::resolve_local_download_path()` must treat an empty string as invalid input and refuse it outright. This guards against misconfigured products or tampered requests that omit the target.

## Steps

1. Stub `wp_upload_dir()` so the allowed root is the temp `wp-content/uploads/ppcart-uploads`.
2. Call `PPCart_Files::resolve_local_download_path('')` with an empty string.

## Expected result

The validator returns `false` for the empty input. No path is resolved and nothing is served.

## Edge cases

- An empty path is rejected before any allowed-root or filesystem resolution occurs, ensuring blank input cannot accidentally resolve to a base or working directory.
