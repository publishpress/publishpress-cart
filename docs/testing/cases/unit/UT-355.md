# Rendered email HTML keeps late escaping without entity decode

## Scenario

`ppcart_get_email_html()` must return sendable HTML. Markup merge tags stay
real tags. Customer text is escaped. Footer `&mdash;` is not double-encoded.
Callers must not `html_entity_decode()` the document.

## Steps

1. Stub footer `{publishpress_cart} &mdash; {customer_firstname}` with first
   name `A & B <a href="https://evil.test">x</a>`.
2. Call `ppcart_get_email_html()` for a registration email.

## Expected result

- Branding `<a href="https://publishpress.com/publishpress-cart/"` is present.
- Footer contains `&mdash;`, not `&amp;mdash;`.
- Customer markup is entity-escaped (`&lt;a href=`). No `href="https://evil.test"`.
- Output contains `A &amp; B`.

## Edge cases

- Headline `esc_html()` and logo `esc_attr()` must still stick without a
  whole-document decode.
