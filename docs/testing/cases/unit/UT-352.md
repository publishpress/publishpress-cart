# Report cron schedules use ppcart_* keys and migrate leftover mt_* options

## Scenario

Summary-report cron recurrences must be `ppcart_daily` / `ppcart_weekly` /
`ppcart_semi_monthly`. Sites that still store leftover `mt_*` values on
`ppcart_report_schedule` must rewrite those options and reschedule the hook
under the prefixed recurrence.

## Steps

1. Call `ppcart_schedule_report_period()` with canonical weekly, semi-monthly,
   and daily keys.
2. Call `ppcart_canonical_report_schedule()` with leftover and unknown slugs.
3. Stub leftover `mt_daily` on `ppcart_report_schedule` and run
   `ppcart_register_report_schedule_event()`.
4. Stub leftover `mt_none` and run the same register function.

## Expected result

1. Windows are 7 / 15 / 1 day. Leftover slugs match the canonical windows.
2. Leftover two-letter slugs become `ppcart_*`; unknown strings pass through.
3. Stored option becomes `ppcart_daily` and `wp_schedule_event` uses that
   recurrence.
4. None clears the cron hook and does not schedule.

## Edge cases

- `ppcart_none` is a stored sentinel, not a `cron_schedules` key.
