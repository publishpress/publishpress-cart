# Rejects a nonexistent file inside the ppcart-uploads directory

## Scenario

Security case. Even when a path correctly points inside the allowed `ppcart-uploads` root, `PPCart_Files::resolve_local_download_path()` must confirm the file actually exists before returning it. Canonicalization via `realpath()` fails for missing files, so a request for a file that is not on disk must resolve to a rejection rather than a fabricated or partial path. This prevents probing for or relying on files that are not really present.

## Steps

1. Stub `wp_upload_dir()` so the allowed root is the temp `wp-content/uploads/ppcart-uploads`.
2. Do not create `<ppcart-uploads>/missing.zip`.
3. Call `PPCart_Files::resolve_local_download_path('<ppcart-uploads>/missing.zip')`.

## Expected result

The validator cannot resolve a real canonical path for the missing file and returns `false`, despite the path being inside the allowed root. Nothing is served.

## Edge cases

- The path is well-formed and inside the allowed directory, so rejection is driven purely by the file's nonexistence, distinguishing this from the boundary-violation cases.
