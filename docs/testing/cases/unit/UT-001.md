# Empty Request With No Screen Is Not A Plugin Admin Screen

## Scenario

When WordPress has not resolved a current screen object and the request carries no plugin signals, `PPCart_Admin_Screens::is_plugin_screen()` must not claim the page. This guards every admin asset/notice that keys off Cart screen detection so they never leak onto unrelated WP-Admin pages. The detector should treat a totally empty context as "not ours".

## Steps

1. Reset the admin screen context so `get_current_screen()` returns `null`, `$_GET`/`$_POST`/`$_REQUEST` are empty, and admin parent / post type state are blank.
2. Call `PPCart_Admin_Screens::is_plugin_screen()` with no hook suffix argument.

## Expected result

`is_plugin_screen()` returns `false`: with no `page` query, no hook suffix, no route params, no screen object, and no known post type/taxonomy there is nothing that identifies the request as a Cart screen.

## Edge cases

- This is the baseline negative: it distinguishes a truly empty admin request from sibling cases that turn `true` once a `page` slug (UT-002), route param (UT-017), or post type query (UT-012) is present.
