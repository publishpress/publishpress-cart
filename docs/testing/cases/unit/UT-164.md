# Known Fallback Labels Are Available When WordPress Has No Status Object

## Scenario

When WordPress has no registered post status object for a given key, `PPCart_Status_Labels::get()` must still return a friendly label from its internal fallback table. This guarantees that recognized cart/subscription statuses always render a clean human-readable name even before (or without) status registration.

## Steps

1. Leave the stubbed `get_post_status_object()` returning `null` for every key (no statuses registered).
2. Call `PPCart_Status_Labels::get('past_due')`.

## Expected result

The method returns `Past Due`, the fallback label mapped to the `past_due` key in the internal label table.

## Edge cases

- Other known keys behave the same way without a status object, e.g. `pending-payment` returns `Pending`, `uncollectible` returns `Uncollectible`, and `trialing` returns `Trialing`.
