# Migration refuses to run while encryption is disabled

## Scenario

Security case. Migrating plaintext secrets only makes sense when encryption is on; running it while the database flag is off would either be a no-op or risk producing data the site cannot decrypt. The migration routine must therefore guard on the flag and return an explicit error when encryption is disabled rather than silently doing nothing.

## Steps

1. Skip if the `PPCART_ENCRYPT_SECRETS` constant is defined.
2. Disable the database flag (remove `ENCRYPT_SECRETS_OPTION`).
3. Call `PPCart_Secrets::migrate_plaintext_secrets()`.
4. Check the result with `is_wp_error()`.

## Expected result

- The routine returns a WP_Error (`is_wp_error()` returns `true`), signaling that migration was refused because at-rest encryption is disabled. No credentials are altered.

## Edge cases

- With the flag enabled the same call performs the migration and returns a `migrated` count array (UT-154); the disabled state is the only path that yields an error.
