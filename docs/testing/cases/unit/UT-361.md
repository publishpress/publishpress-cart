# Profile AJAX validates the new password strictly and keeps it unchanged

## Scenario

`ppcart_update_user_profile()` reads a serialized `form_data` string. The new
password and its confirmation must match exactly. The password itself is not
sanitized, because sanitizing would change it (same as core).

## Steps

1. Post `password=1e3` and `new_password=1000`.
2. Post `password[]=a` and `new_password[]=a`.
3. Post the same password with spaces, `<`, `>` and `%41` in both fields.

## Expected result

1. The handler returns an error and does not call `wp_set_password()`.
2. The handler ignores the array values and does not call `wp_set_password()`.
3. The handler calls `wp_set_password()` once with the exact posted password.

## Edge cases

- Loose `!=` treats `1e3` and `1000` as equal. The handler must use a strict check.
