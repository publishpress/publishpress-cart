# Stored Core Email Option Value Is Preserved

## Scenario

Canonical email option reads must preserve a stored `_ppcart_email_completed_subject` value instead of falling back to the template default. Leftover `_sc_*` copy-on-read lives in publishpress-cart-compat.

## Steps

1. Store `_ppcart_email_completed_subject` = `Custom complete subject`.
2. Call `get_option('_ppcart_email_completed_subject')`.
3. Run the option-read portion of `ppcart_notification_send('completed', ...)` and capture every requested option key.

## Expected result

- `get_option('_ppcart_email_completed_subject')` returns `Custom complete subject`, not the template default.
- The notification sender requests `_ppcart_email_completed_subject`, `_ppcart_email_completed_headline`, and `_ppcart_email_completed_body`, and never directly requests `_sc_email_completed_subject`.

## Edge cases

- The `_sc_email_completed_subject` key remains the persisted storage row for backward data compatibility; first-party PHP uses only the canonical `_ppcart_email_completed_subject` option API.
