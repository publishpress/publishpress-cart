# Core Email Option Default Filter Is Registered During File Load

## Scenario

For each core email option, `ppcart_register_email_template_option_filters()` must hook the WordPress `default_option_<option>` filter so an unset option falls back to the plugin's template default. This case verifies that the default-resolution filter for the canonical "order complete" subject option `_ppcart_email_completed_subject` is attached exactly once during the file-load registration pass.

## Steps

1. Load `ppcart-email-template-functions.php`, which calls `ppcart_register_email_template_option_filters()` at file scope.
2. For `_ppcart_email_completed_subject`, the registrar calls `add_filter('default_option__ppcart_email_completed_subject', 'ppcart_email_template_default_option', 10, 2)`.
3. Count the callbacks registered against the `default_option__ppcart_email_completed_subject` hook in the stub filter registry.

## Expected result

- The `default_option__ppcart_email_completed_subject` hook has exactly `1` registered callback (`ppcart_email_template_default_option`), at priority `10` accepting `2` args.

## Edge cases

- Even though many core options exist, the count for this specific hook must be `1` (not aggregated across options), confirming per-option registration rather than a single global filter.
