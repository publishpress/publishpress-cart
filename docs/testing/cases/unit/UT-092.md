# Partial Refund Is Detected As Partial Refund State

## Scenario

`PPCart_Order_Refunds::is_partially_refunded()` returns `true` only when an order has a refund total that is greater than zero but strictly less than its gross amount. For a $200.00 order refunded by $100.00, the refund sits between those bounds, so the order is in a partial-refund state.

## Steps

1. Seed order `667` post meta with `_sc_amount = "200.00"`, `_sc_refund_amount = "100.00"`, and a `_sc_refund_log` entry keyed `re_partial` with `amount = "100.00"`.
2. Call `PPCart_Order_Refunds::is_partially_refunded(667)`.
3. The method computes gross (200.00) and refund total (100.00), then evaluates `refund_total > 0 && refund_total < gross`.

## Expected result

The method returns `true` because `100.00 > 0` and `100.00 < 200.00`.

## Edge cases

- A refund total equal to or greater than the gross amount returns `false` (full/over refund, covered separately).
- A gross amount of `0` short-circuits to `false` before the comparison runs.
