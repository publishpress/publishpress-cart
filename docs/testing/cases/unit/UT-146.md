# At-rest encryption stays off when the database flag is absent

## Scenario

Security case. At-rest encryption of sensitive options must default to OFF so the plugin never silently encrypts with a key the admin has not opted into. When the database control option (`ENCRYPT_SECRETS_OPTION`) is not set, `PPCart_Secrets` must report encryption as disabled and expose `disabled` as the control source, so callers can detect that secrets are stored as plaintext.

## Steps

1. Skip if the `PPCART_ENCRYPT_SECRETS` wp-config constant is defined (that is a separate production override, not the database flag under test).
2. Force the database flag off by removing `ENCRYPT_SECRETS_OPTION` from the options store (`setDbEncryptionEnabled(false)`).
3. Read `PPCart_Secrets::is_db_encryption_enabled()`, `PPCart_Secrets::encryption_enabled()`, and `PPCart_Secrets::get_encryption_control_source()`.

## Expected result

- `is_db_encryption_enabled()` returns `false`.
- `encryption_enabled()` returns `false`, confirming new sensitive option writes are stored as plaintext rather than encrypted.
- `get_encryption_control_source()` returns the exact string `'disabled'`.

## Edge cases

- If the wp-config constant `PPCART_ENCRYPT_SECRETS` is present in the PHP process, the database flag is not authoritative and the test is skipped to avoid asserting on the wrong control source.
