# Allows download of a file located inside the ppcart-uploads directory

## Scenario

Security case. The download resolver `PPCart_Files::resolve_local_download_path()` must only hand back files that physically live inside the allowed `wp-content/uploads/ppcart-uploads` directory. This case proves the positive path: a real absolute filesystem path pointing at a file that exists inside `ppcart-uploads` is accepted and its canonical (symlink/`..`-free) location is returned. This is the baseline guarantee that legitimate product downloads keep working while everything outside the allowed root is blocked by sibling cases.

## Steps

1. Stub `wp_upload_dir()` so its `basedir` is the temp `wp-content/uploads`, making `wp-content/uploads/ppcart-uploads` the allowed download root.
2. Place a real file at `<ppcart-uploads>/product.zip`.
3. Call `PPCart_Files::resolve_local_download_path('<ppcart-uploads>/product.zip')` with that absolute path.

## Expected result

The validator accepts the path and returns the resolved canonical path `realpath('<ppcart-uploads>/product.zip')` (a non-empty string equal to the real file location), rather than `false`. The returned value is the actual file path the download handler may safely stream.

## Edge cases

- The returned value is the `realpath()`-normalized path, so even if the input contained a symlink or redundant separators inside the allowed root, the canonical path is what gets returned and later served.
- Leftover `sc-uploads` is not a first-party allowed root (IT-361 / Compat extra root only).
