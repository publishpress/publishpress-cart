# Settings Page Query Is Specifically Detected As The Settings Screen

## Scenario

Beyond being "a plugin screen", the `?page=ppcart-settings` request must be identified as the settings screen in particular via `PPCart_Admin_Screens::is_settings_screen()`. Settings-only behavior (settings assets, tabs, save handlers) depends on this narrower check matching the `ppcart-settings` page slug against `PAGE_SETTINGS`.

## Steps

1. Reset the admin screen context with `$_GET['page'] = 'ppcart-settings'` and no screen object.
2. Call `PPCart_Admin_Screens::is_settings_screen()`.

## Expected result

`is_settings_screen()` returns `true`: the current `page` equals the settings slug `ppcart-settings`, so the request is detected as the settings screen.

## Edge cases

- Distinguishes the precise settings check from the broad `is_plugin_screen()` check (UT-002); UT-011 confirms a foreign `ppcart-settings`-containing id is not a settings screen.
