# Addon Email Option Filter Is Not Registered Before Addon Declares Option Name

## Scenario

Add-on email options are not part of the core static list, so their filters should only be registered once the add-on declares the option name via the `ppcart_email_template_option_names` filter. This case verifies the negative precondition: before any add-on declares `_ppcart_email_addon_subject`, no `default_option_*` filter exists for it.

## Steps

1. Load `ppcart-email-template-functions.php` and let the file-load pass run, without adding any `ppcart_email_template_option_names` filter for the add-on option.
2. Count callbacks registered against `default_option__ppcart_email_addon_subject` in the stub filter registry.

## Expected result

- The `default_option__ppcart_email_addon_subject` hook has `0` registered callbacks, because the add-on option name was never present in `ppcart_email_template_option_names()` during registration.

## Edge cases

- This establishes the baseline for the late-pass case: registration is strictly driven by declared option names, never by guessing add-on option keys.
