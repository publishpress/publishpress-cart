# Foreign Screen Ids Containing "ppcart-settings" Are Not The Settings Screen

## Scenario

A foreign admin page id such as `tools_page_my-ppcart-settings-helper` embeds the substring `ppcart-settings`, which is the Cart settings page slug. `PPCart_Admin_Screens::is_settings_screen()` must require an exact page/hook match, not a substring, so an unrelated tool page is never mistaken for Cart settings.

## Steps

1. Reset the admin screen context with a screen object `{ id: 'tools_page_my-ppcart-settings-helper', base: 'tools_page_my-ppcart-settings-helper' }`.
2. Call `PPCart_Admin_Screens::is_settings_screen()`.

## Expected result

`is_settings_screen()` returns `false`: neither the page slug nor the screen id/base exactly equals `ppcart-settings` or the hook `ppcart_page_ppcart-settings`, so the embedded `ppcart-settings` substring is ignored.

## Edge cases

- Substring-vs-exact boundary for the settings check, mirroring UT-009 for the general plugin-screen check.
