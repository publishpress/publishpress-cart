# A post ID or global post of a Cart record does not hijack another screen

## Steps

1. Reset the admin screen context for the Pages list (`edit-page`, base `edit`, post type `page`) with `post=123` in the URL, while `get_post_type()` returns `ppcart_product`.
2. Reset it again for another plugin's edit screen (base `post`, post type `tribe_events`) with `post=456`, while `get_post_type()` returns `ppcart_product`.
3. Call `is_plugin_screen()` and `is_post_type_screen('ppcart_product')` each time.

## Expected result

All calls return false: the current post type comes from the screen, not from a post ID in the URL or the global $post.
