# get_decrypted_option lazily migrates plaintext to ciphertext when encryption is on

## Scenario

Security case. When encryption is enabled, reading a sensitive option that is still stored as plaintext is an opportunity to opportunistically encrypt it at rest. `get_decrypted_option()` must return the correct plaintext to the caller while upgrading the stored value to ciphertext, shrinking the window in which credentials sit unencrypted.

## Steps

1. Skip if OpenSSL is unavailable, and skip if the `PPCART_ENCRYPT_SECRETS` constant is defined.
2. Enable the database flag (`ENCRYPT_SECRETS_OPTION` = `'1'`).
3. Seed `_sc_stripe_test_sk` as plaintext `sk_test_lazy_migration_on_read` in both raw and decrypted stores.
4. Call `PPCart_Secrets::get_decrypted_option('_sc_stripe_test_sk')` and inspect the raw stored value afterward.

## Expected result

- The call returns the plaintext `sk_test_lazy_migration_on_read` to the caller.
- The raw stored value of `_sc_stripe_test_sk` is now encrypted (`is_encrypted_value()` returns `true`), demonstrating lazy migration on read.

## Edge cases

- When encryption is disabled, this lazy upgrade must not happen and the value stays plaintext (covered by UT-161).
