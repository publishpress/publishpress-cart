# Log directories write HTML guards not PHP

## Scenario

WordPress.org forbids generated PHP. Debug and Stripe webhook loggers must
create an empty `index.html` listing guard under their log folder and must not
leave an `index.php` behind, including leftover PHP guards from older installs.

## Steps

1. Call `PPCart_Debug_Logger::ensure_log_directory()` on a temp log folder.
2. Call it again after seeding a leftover `index.php`.
3. Call `PPCart_Stripe_Webhook_Logger::ensure_log_directory()` on a stubbed
   uploads `publishpress-cart/logs` folder, including a leftover-`index.php` run.

## Expected result

- `index.html` exists and contains no `<?php`.
- `index.php` is absent after each call.

## Edge cases

- A pre-existing generated PHP guard must be removed on the next ensure.
