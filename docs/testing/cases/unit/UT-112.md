# Recurring Payment Plan Option ID Is Preserved

## Scenario

The recurring plan's `option_id` is referenced by integrations and confirmations, so it must remain stable on the duplicate. This verifies the second `_sc_pay_options` row keeps its `option_id`.

## Steps

1. Seed the source with a second (recurring) plan row whose `option_id` is `'plan_recurring'`.
2. Duplicate it.
3. Read `_sc_pay_options[1]['option_id']` from the duplicate.

## Expected result

`_sc_pay_options[1]['option_id']` equals `'plan_recurring'`, preserved exactly on the copy.

## Edge cases

- Keeping this id stable is what lets the copied integration restriction still resolve (UT-117); it is a local id, not a Stripe id.
