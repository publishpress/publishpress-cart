# Flow Group Keeps Final Checkout Event Last

## Scenario

Complementing the oldest-first ordering, the most recent event in a flow group must sit at the end of the timeline. This case verifies the last entry of the `unit-checkout-1` group is the order-saved event.

## Steps

1. Log a validation-started event followed by an order-saved event (Order #702) under `flow_id` `unit-checkout-1`.
2. Build groups via `group_entries()` and select the `flow:unit-checkout-1` group.
3. Inspect `entries[1]['message']` of that group.

## Expected result

- The group's final timeline entry message is `Order #702 saved successfully.`, the newest event in the flow.

## Edge cases

- Adding more events to the flow should keep the most recent one positioned last.
