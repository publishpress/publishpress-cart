# Admin conditional-logic JS encodes interpolants

## Scenario

Product and order metabox conditional-logic snippets must JSON-encode field
values and compare tokens before `wp_add_inline_script`, so admin field data
cannot break out of inline JavaScript.

## Steps

1. Build JS for a rule whose value contains quotes and a script-like substring.
2. Build JS for a rule with a non-allowlisted compare operator.
3. Build JS for an `IN` rule on a service field.
4. Build JS for a checkbox rule with boolean true value.

## Expected result

1. Output contains JSON-encoded value, not raw `</script>` or unescaped quotes.
2. Output uses `==` instead of the hostile compare token.
3. Output references `#services` (field id) and a JSON array literal.
4. Output includes a `:checked` selector.

## Edge cases

- Order metabox uses per-rule blocks via a separate helper entry point.
