# Flow Group Keeps Related Checkout Events Together

## Scenario

A flow group should contain exactly the entries that share its `flow_id`, no more and no less. This case verifies the `unit-checkout-1` group bundles both of its events while excluding the unrelated `unit-checkout-2` event.

## Steps

1. Log two events under `flow_id` `unit-checkout-1` and one under `unit-checkout-2`.
2. Build groups via `group_entries()` and select the `flow:unit-checkout-1` group.
3. Inspect the group's `event_count` field.

## Expected result

- The `flow:unit-checkout-1` group's `event_count` is `2`, confirming only its two events are grouped together.

## Edge cases

- An unrelated event with a different flow id must not inflate this group's count.
