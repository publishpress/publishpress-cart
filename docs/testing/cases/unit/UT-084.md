# Addon Email Option Default Filter Is Registered By Late Pass

## Scenario

When an add-on declares its option name through the `ppcart_email_template_option_names` filter and supplies a matching template via `ppcart_email_templates`, the re-run of `ppcart_register_email_template_option_filters()` (the `init` priority `99` pass) must pick up the new option and register its `default_option_*` filter. This case simulates that add-on registration and confirms the filter is wired.

## Steps

1. Add a `ppcart_email_template_option_names` filter that appends `_ppcart_email_addon_subject` to the option-name list.
2. Add a `ppcart_email_templates` filter that adds an `addon` template whose `subject` maps to option `_ppcart_email_addon_subject` with default `Addon default`.
3. Call `ppcart_register_email_template_option_filters()` again to emulate the late `init`/priority-`99` pass.
4. Count callbacks registered against `default_option__ppcart_email_addon_subject`.

## Expected result

- The `default_option__ppcart_email_addon_subject` hook now has exactly `1` registered callback (`ppcart_email_template_default_option`), proving the late pass registers add-on-declared options.

## Edge cases

- The add-on option is only registered after it appears in `ppcart_email_template_option_names()`; the registrar's static `$registered` map ensures it is added on the first pass that sees it and not re-added later.
