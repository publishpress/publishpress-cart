# Structured Event Context Drives Workflow Detection

## Scenario

Newer log lines append a structured `context={...}` JSON payload carrying an `event` name. When present, this event name should drive workflow classification more reliably than message text. This case verifies a `checkout.payment_intent.created` event maps the entry to the `Checkout` workflow.

## Steps

1. Call `PPCart_Debug_Log_Viewer::parse_line()` with `[05/12/2026 6:32 AM] - STATUS : Stripe PaymentIntent created successfully. context={"event":"checkout.payment_intent.created","order_id":627,"client_secret":"pi_secret","charge_id":"ch_123"}`.
2. Inspect the `workflow` field of the returned parsed array.

## Expected result

- The parsed entry's `workflow` is `Checkout`, inferred from the `event` prefix in the structured context.

## Edge cases

- If the context JSON is malformed, the parser should fall back to message-based detection rather than failing.
