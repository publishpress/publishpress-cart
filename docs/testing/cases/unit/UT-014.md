# Single Product Editor Is A Plugin Screen

## Scenario

Editing a single Cart product opens `post.php` with a screen object whose `base` is `post` and `post_type` is `ppcart_product`. `PPCart_Admin_Screens::is_plugin_screen()` must recognize this editor via the screen's post type so Cart admin UI loads on the product edit page.

## Steps

1. Reset the admin screen context with a screen object `{ id: 'ppcart_product', base: 'post', post_type: 'ppcart_product' }`.
2. Call `PPCart_Admin_Screens::is_plugin_screen()`.

## Expected result

`is_plugin_screen()` returns `true`: the screen's `post_type` `ppcart_product` is in the known post types, so the single-product editor is a plugin screen.

## Edge cases

- Sets up UT-015, which uses the same product-editor context but asserts it is excluded from version notices — same screen, narrower rule.
