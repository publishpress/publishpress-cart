# Legacy Past-Due Aliases Still Resolve Through Current Option Names

## Scenario

The canonical email API retains the historical `past_due` → `failed` semantic alias. `ppcart_email_template_alias_options()` maps `_ppcart_email_past_due_enable` to `_ppcart_email_failed_enable`. Leftover `_sc_*` copy-on-read lives in publishpress-cart-compat.

## Steps

1. Store `_ppcart_email_failed_enable` = `'1'`.
2. Call `get_option('_ppcart_email_past_due_enable')`.

## Expected result

- `get_option('_ppcart_email_past_due_enable')` returns `'1'` via the canonical `past_due` → `failed` alias.

## Edge cases

- The semantic alias is one-directional (`past_due` → `failed`); `_sc_email_failed_*` remains the persisted row, while first-party PHP uses `_ppcart_email_failed_*`.
