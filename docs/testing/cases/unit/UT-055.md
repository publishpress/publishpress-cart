# Log Event Adds Request Flow Id For Grouping

## Scenario

To let the viewer cluster all log lines from one request, `log_event()` stamps every entry with a `flow_id` even when the caller does not supply one. This case verifies a written event carries a non-empty `flow_id`.

## Steps

1. Instantiate `PPCart_Debug_Logger` and call `log_event('checkout.order.saved', 'Order saved successfully.', ['order_id' => 701, 'status' => 'paid', 'client_secret' => 'secret_value'], 0)`.
2. Call `PPCart_Debug_Log_Viewer::read_entries(['limit' => 10, 'search' => '701'])`.
3. Inspect the first entry's `flow_id` field.

## Expected result

- `entries[0]['flow_id']` is non-empty, providing a grouping key for the request.

## Edge cases

- Multiple events logged within the same request should share one auto-generated `flow_id`.
