# Cancellation refund rejects invoices with nothing left to refund

## Scenario

If the invoice's paid amount has already been fully credited, there is nothing left to refund and Stripe would reject a zero/negative credit note. The cancellation refund flow guards against this by throwing before calling Stripe. This test confirms the function fails loudly when the refundable amount computes to zero.

## Steps

1. Build a Stripe client stub whose latest invoice `in_empty` has `amount_paid = 1000` and `post_payment_credit_notes_amount = 1000`, so the remaining refundable amount is `0`.
2. Call `ppcart_issue_stripe_subscription_cancellation_refund()` with order `{ id: 321, subscription_id: 'sub_test' }` and subscription `{ id: 'sub_empty', latest_invoice: 'in_empty' }`, wrapped in a try/catch.
3. Inspect the thrown exception's message.

## Expected result

An exception is thrown whose message contains "no refundable paid amount"; no credit note is created.

## Edge cases

- The boundary case where `amount_paid` equals `post_payment_credit_notes_amount` (here `1000 == 1000`) yields `0` and is treated as non-refundable, not as a valid zero-amount credit note.
