# Debug Log View Handler Returns Early When No Log Action Is Requested

## Scenario

Security/access-control case. On the plugin settings page the `view_log_request()` handler must do nothing unless an explicit log action is requested. When the request lands on the settings page (`page=ppcart-settings`) but carries no `ppcart_view_log` or `ppcart_download_log` parameter, the handler must return early before any capability check, nonce verification, or output. This keeps normal settings-page loads from triggering log access logic.

## Steps

1. Simulate a request where `$_REQUEST['page']` is `ppcart-settings` and no log-action parameter is present.
2. Simulate the current user lacking the `manage_options` capability.
3. Call `PPCart_Debug_Logger::view_log_request()`.

## Expected result

The handler returns early without acting: `wp_die()` is never invoked and the nonce check (`check_admin_referer`) is never reached. With no action requested, the handler exits before evaluating the `manage_options` capability or any nonce.

## Edge cases

- Even on the correct settings page, the absence of a log action must prevent any capability or nonce evaluation — no side effects on ordinary page loads.
