# Rejects an absolute path outside the allowed upload directory

## Scenario

Security case. An attacker who controls a download target could supply an absolute filesystem path to a sensitive file outside the uploads area. `PPCart_Files::resolve_local_download_path()` must refuse any absolute path that does not live inside the allowed `ppcart-uploads` root. This case targets the classic exposure: pointing the resolver straight at `wp-config.php`, which sits above the uploads directory and holds DB credentials and secret keys.

## Steps

1. Stub `wp_upload_dir()` so the allowed root is the temp `wp-content/uploads/ppcart-uploads`.
2. Place a real `wp-config.php` at the temp project root, i.e. outside the uploads directory.
3. Call `PPCart_Files::resolve_local_download_path('<tempRoot>/wp-config.php')`.

## Expected result

The validator rejects the path and returns `false` (not the path). Even though the file genuinely exists and is readable, it is outside the allowed root, so it is never resolved or served.

## Edge cases

- The target file actually exists, confirming rejection is driven by the allowed-root boundary check and not merely by a missing-file failure.
