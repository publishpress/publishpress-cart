# get_decrypted_option falls back to decrypt a value that is still encrypted

## Scenario

Security case. `get_decrypted_option()` should always hand callers usable plaintext. Even if the value coming back from the option store is still in encrypted form (for example because another code path returned the raw blob), the helper must detect this and decrypt it as a fallback rather than leaking ciphertext to the integration.

## Steps

1. Skip if OpenSSL is unavailable.
2. Encrypt the plaintext `ac-secret-key-value` with `encrypt_value()`.
3. Store the encrypted blob directly as the option `_sc_activecampaign_secret_key`.
4. Call `PPCart_Secrets::get_decrypted_option('_sc_activecampaign_secret_key')`.

## Expected result

- The helper returns the decrypted `ac-secret-key-value`, applying the fallback decryption so the caller never receives the raw encrypted blob.

## Edge cases

- If the value were already plaintext, the helper would return it directly without attempting a second decryption.
