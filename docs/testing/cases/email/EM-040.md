# Subscription Renewal — enabled sends

## Scenario

Automated by `tests/playwright/admin/email-040-renewal-enabled-sends.spec.ts`. With **Subscription
Renewal Confirmation** turned on from the Emails settings tab, a `renewal` status change delivers the
customer email.

## Steps

1. Skip unless admin credentials and the email fixture ids (`composer test:admin:setup`) are present.
2. Open `<site>/wp-admin/admin.php?page=ppcart-settings#emails` and confirm `#content_tab_emails`.
3. Open the `emailtemplate_renewal` Manage modal.
4. Turn `_ppcart_email_renewal_enable` on by clicking `label[for="_ppcart_email_renewal_enable"]`; the
   input is `display: none`, so `check()` cannot be used.
5. Save from inside the modal and wait for the `settings-updated=true` redirect.
6. Assert the "Subscription Renewal Confirmation" row status dot renders `is-enabled`.
7. Empty the Mailpit mailbox.
8. POST the fixtures trigger `order_status` for the seeded **order** with status `renewal` and a
   unique `@example.invalid` recipient.

## Expected result

1. A Mailpit message addressed to that recipient arrives within the wait window.
2. Its subject is not empty.

## Edge cases

- Despite the name, `renewal` is not one of the statuses `ppcart_notification_send()` builds a
  `PPCart_Subscription` for, so this fires against the order fixture. Only EM-060/EM-061 use the
  subscription fixture.
