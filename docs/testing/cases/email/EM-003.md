# Pending — admin copy

## Scenario

Automated by `tests/playwright/admin/email-003-pending-admin-copy.spec.ts`. With the companion
`_ppcart_email_pending_admin` option on, `ppcart_notification_send()` addresses a second copy of the
same composed email to the store admin.

## Steps

1. Skip unless admin credentials and the email fixture ids (`composer test:admin:setup`) are present.
2. Open the Emails tab via the `#emails` hash and open the Order Received Confirmation Manage modal.
3. Set both `_ppcart_email_pending_enable` and `_ppcart_email_pending_admin` on by clicking their
   `label[for=...]` elements — the inputs are `display: none`, so `check()` cannot be used — then save
   once from inside the modal; the tab shares a single form, so both land in the same POST.
4. Assert the row status dot renders `is-enabled`.
5. Resolve the admin recipient the same way `ppcart_notification_send()` does: first address in
   `#ppcart_admin_email`, or the WordPress General Settings admin email when that field is empty.
   The Cart option is shared with the reports scheduler and is never written by this spec.
6. Empty the Mailpit mailbox.
7. POST the fixtures trigger `order_status` for the seeded order with status `pending` and a unique
   `@example.invalid` recipient.
8. Turn the admin copy back off through the same modal.

## Expected result

1. A message addressed to the customer recipient arrives.
2. A message addressed to the admin address arrives.
3. The two share a subject but are distinct Mailpit records — the admin copy is the same composed
   email, re-addressed.

## Edge cases

- The admin address falls back to WordPress `admin_email` when `ppcart_admin_email` is empty.
- The admin copy is switched off again at the end so later specs are not surprised by a second
  message.
