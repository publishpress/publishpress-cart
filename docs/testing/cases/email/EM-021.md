# New User Welcome — disabled does not send

## Scenario

Automated by `tests/playwright/admin/email-021-registration-disabled-does-not-send.spec.ts`. The
mirror of EM-020: with **New User Welcome** turned off, creating a customer account must deliver
nothing. "Off" here has to mean the plugin decided not to send, not that WordPress sent it instead.

## Steps

1. Skip unless admin credentials and the email fixture ids (`composer test:admin:setup`) are present.
2. Open the Emails tab via the `#emails` hash and open the `emailtemplate_registration` Manage modal.
3. Turn `_ppcart_email_registration_enable` off and force `_ppcart_use_wp_notification` off as well,
   both by clicking their `label[for=...]` elements since the inputs are `display: none`. Left on, the
   WP-notification option would still produce a mail and the spec would fail for the wrong reason.
4. Save from inside the modal and wait for the `settings-updated=true` redirect.
5. Assert the row status dot renders `is-disabled` before any trigger fires.
6. Empty the Mailpit mailbox.
7. POST the fixtures trigger `create_user` for the seeded order with a unique `@example.invalid`
   recipient.

## Expected result

1. No Mailpit message addressed to that recipient arrives during the full quiet window.

## Edge cases

- The trigger helper throws unless the endpoint reports success, and the endpoint reports whether the
  user was created or already existed, so "nothing arrived" cannot be explained away by a trigger
  that never ran.
- The address is unique per run so `ppcart_create_user()` takes the create branch rather than the
  already-exists branch.
