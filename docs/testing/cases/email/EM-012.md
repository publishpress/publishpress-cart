# Purchase Confirmation — sends with invoice attached

## Scenario

Automated by `tests/playwright/admin/email-012-purchase-invoice-attachment.spec.ts`. With Purchase
Confirmation enabled **and** `_ppcart_invoice_attach_confirmation_email` on, the delivered message
carries the invoice PDF.

This is the regression guard for the `get_invoice()` fatal fixed in commit `a559433f`:
`PPCart_Order::get_invoice()` required a stale relative path and fatalled **before** `wp_mail()`, so
the enabled setting still delivered nothing whenever the attach-invoice option was on. EM-010 and
EM-011 alone do not catch that — only the attachment path does.

## Steps

1. Skip unless admin credentials and the email fixture ids (`composer test:admin:setup`) are present.
2. Enable Purchase Confirmation through the Emails tab: open the `#emails` hash URL, open the
   `emailtemplate_purchase` modal, click `label[for="_ppcart_email_confirmation_enable"]` (the input
   is `display: none`, so `check()` cannot be used), save in-modal, and assert the row dot is
   `is-enabled`.
3. Open `<site>/wp-admin/admin.php?page=ppcart-settings#invoice`. The attach-invoice checkboxes live
   on the Invoices tab, not in an email modal, so they use the plain tab plus bottom-save path.
4. Turn `_ppcart_invoice_attach_confirmation_email` on by clicking its `label[for=...]`, save with
   `[data-testid="ppcart-admin-settings-save-bottom"]`, and wait for the `settings-updated=true`
   redirect.
5. Reload the Invoices tab and re-read the checkbox from that fresh render, so the assertion reflects
   `get_option()` rather than the DOM just clicked into place.
6. Empty the Mailpit mailbox.
7. POST the fixtures trigger `order_status` for the seeded order with status `paid` and a unique
   `@example.invalid` recipient.
8. Restore `_ppcart_invoice_attach_confirmation_email` to off in a `finally` block.

## Expected result

1. A Mailpit message addressed to that recipient arrives.
2. Its list summary reports at least one attachment.
3. The full message record holds at least one attachment and the first attachment filename ends in
   `.pdf`.

## Edge cases

- The attachment is switched back off at the end because the other confirmation specs assert on plain
  mail.
- Two saves through the shared settings form make this the slowest spec in the suite; it runs with an
  extended timeout.
