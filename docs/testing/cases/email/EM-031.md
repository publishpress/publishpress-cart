# Order Refunded — disabled does not send

## Scenario

Automated by `tests/playwright/admin/email-031-refunded-disabled-does-not-send.spec.ts`. The mirror of
EM-030: with **Order Refunded** turned off, a `refunded` order transition must deliver nothing.

## Steps

1. Skip unless admin credentials and the email fixture ids (`composer test:admin:setup`) are present.
2. Open the Emails tab via the `#emails` hash and open the `emailtemplate_refunded` Manage modal.
3. Turn `_ppcart_email_refunded_enable` off by clicking its `label[for=...]`, because the input is
   `display: none` and `uncheck()` cannot act on it.
4. Save from inside the modal and wait for the `settings-updated=true` redirect.
5. Assert the row status dot renders `is-disabled` before any trigger fires.
6. Empty the Mailpit mailbox.
7. POST the fixtures trigger `order_status` for the seeded order with status `refunded` and a unique
   `@example.invalid` recipient.

## Expected result

1. No Mailpit message addressed to that recipient arrives during the full quiet window.

## Edge cases

- The trigger helper throws unless the endpoint reports success, so a never-fired trigger cannot pass
  as a suppressed email.
