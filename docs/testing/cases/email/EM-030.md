# Order Refunded — enabled sends

## Scenario

Automated by `tests/playwright/admin/email-030-refunded-enabled-sends.spec.ts`. With **Order
Refunded** turned on from the Emails settings tab, an order moving to status `refunded` delivers the
customer email.

## Steps

1. Skip unless admin credentials and the email fixture ids (`composer test:admin:setup`) are present.
2. Open `<site>/wp-admin/admin.php?page=ppcart-settings#emails` and confirm `#content_tab_emails`.
3. Open the `emailtemplate_refunded` Manage modal.
4. Turn `_ppcart_email_refunded_enable` on by clicking `label[for="_ppcart_email_refunded_enable"]`;
   the input is `display: none`, so `check()` cannot be used.
5. Save from inside the modal and wait for the `settings-updated=true` redirect.
6. Assert the "Order Refunded" row status dot renders `is-enabled` before anything is fired.
7. Empty the Mailpit mailbox.
8. POST the fixtures trigger `order_status` for the seeded **order** with status `refunded` and a
   unique `@example.invalid` recipient.

## Expected result

1. A Mailpit message addressed to that recipient arrives within the wait window.
2. Its subject is not empty.

## Edge cases

- `refunded` is not in `ppcart_notification_send()`'s subscription status list, so it builds a
  `PPCart_Order` — the order fixture is the right target, not the subscription fixture.
