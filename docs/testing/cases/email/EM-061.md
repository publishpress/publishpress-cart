# Subscription Canceled — disabled does not send

## Scenario

Automated by `tests/playwright/admin/email-061-canceled-disabled-does-not-send.spec.ts`. The mirror of
EM-060: with **Subscription Canceled Confirmation** turned off, cancelling a subscription must deliver
nothing.

## Steps

1. Skip unless admin credentials and the email fixture ids (`composer test:admin:setup`) are present.
2. Open the Emails tab via the `#emails` hash and open the `emailtemplate_canceled` Manage modal.
3. Turn `_ppcart_email_canceled_enable` off by clicking its `label[for=...]`, because the input is
   `display: none` and `uncheck()` cannot act on it.
4. Save from inside the modal and wait for the `settings-updated=true` redirect.
5. Assert the row status dot renders `is-disabled` before any trigger fires.
6. Empty the Mailpit mailbox.
7. POST the fixtures trigger `subscription_status` for the seeded subscription with status `canceled`
   and a unique `@example.invalid` recipient.

## Expected result

1. No Mailpit message addressed to that recipient arrives during the full quiet window.

## Edge cases

- The trigger builds a `PPCart_Subscription`, so the subscription fixture must exist; the spec skips
  when `composer test:admin:setup` has not seeded it.
