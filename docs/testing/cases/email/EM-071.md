# Pro-locked email rows have no working Enable control

## Scenario

Automated by `tests/playwright/admin/email-071-pro-locked-rows.spec.ts`. The Emails tab renders eleven
notification rows in the free plugin: seven functional ones and the four Pro-locked types from
`ppcart_pro_locked_emails()` — Order Complete Notification, Trial Ending Reminder, Upcoming Renewal
Reminder, and Subscription Paused Confirmation. The locked rows must carry no control capable of
changing an option. No mail is involved.

## Steps

1. Skip unless admin credentials and the email fixture ids (`composer test:admin:setup`) are present.
2. Open `<site>/wp-admin/admin.php?page=ppcart-settings#emails` and confirm `#content_tab_emails`.
3. Count rows by class: `.ppcart-settings__email-notifications-row--locked` and the
   `:not(...--locked)` complement.
4. For each of the four Pro titles, locate its locked row and inspect the action cell.
5. For each of the seven free types, locate its functional row and inspect the action cell.
6. Open the Order Received Confirmation Manage modal as a final control check.

## Expected result

1. Exactly 4 locked rows and exactly 7 functional rows, matching the 4 titles in
   `PRO_LOCKED_EMAIL_TITLES` and the 7 keys in `EMAIL_TYPES`.
2. Each locked row has exactly one `a.ppcart-settings__pro-lock` whose `href` points at
   publishpress.com, and zero `button.ppcart-settings__email-manage`, zero `[data-pp-email-modal-open]`
   triggers, zero `input` elements, and zero `[data-testid]` attributes.
3. Each functional row has exactly one
   `button[data-testid="ppcart-admin-email-emailtemplate-<key>-manage"]` and no Pro lock link.
4. That Manage button really opens a modal containing a live `_ppcart_email_pending_enable` checkbox,
   so "functional" is more than a class name.

## Edge cases

- The counts are exact, so a Pro row leaking a working control — or a free row losing one — fails here
  rather than silently in a send/no-send spec.
- The absent `data-testid` on locked rows is asserted deliberately, so no later spec can reach for one
  by mistake.
- `_ppcart_email_completed_enable` is referenced by `ppcart_email_templates()` but has no field in
  `core-settings.php`, so it can never be enabled from the UI in free; the locked-row assertion is its
  only coverage.
