# Subscription Canceled — enabled sends

## Scenario

Automated by `tests/playwright/admin/email-060-canceled-enabled-sends.spec.ts`. With **Subscription
Canceled Confirmation** turned on from the Emails settings tab, cancelling a subscription delivers the
customer email. `canceled` is one of the statuses `ppcart_notification_send()` builds a
`PPCart_Subscription` for, so this is the one free type driven off the subscription fixture.

## Steps

1. Skip unless admin credentials and the email fixture ids (`composer test:admin:setup`) are present.
2. Open `<site>/wp-admin/admin.php?page=ppcart-settings#emails` and confirm `#content_tab_emails`.
3. Open the `emailtemplate_canceled` Manage modal.
4. Turn `_ppcart_email_canceled_enable` on by clicking `label[for="_ppcart_email_canceled_enable"]`;
   the input is `display: none`, so `check()` cannot be used.
5. Save from inside the modal and wait for the `settings-updated=true` redirect.
6. Assert the "Subscription Canceled Confirmation" row status dot renders `is-enabled`.
7. Empty the Mailpit mailbox.
8. POST the fixtures trigger `subscription_status` for the seeded **subscription** with status
   `canceled` and a unique `@example.invalid` recipient.

## Expected result

1. A Mailpit message addressed to that recipient arrives within the wait window.
2. Its subject is not empty.

## Edge cases

- This is the only case in the suite that acts on the subscription fixture; every other free type
  routes through the order fixture.
