# Purchase Confirmation — enabled sends

## Scenario

Automated by `tests/playwright/admin/email-010-purchase-enabled-sends.spec.ts`. With **Purchase
Confirmation** turned on from the Emails settings tab, an order moving to status `paid` delivers the
customer email. `ppcart_notification_send()` maps status `paid` onto type `confirmation`; there is no
`_ppcart_email_paid_enable`.

## Steps

1. Skip unless admin credentials and the email fixture ids (`composer test:admin:setup`) are present.
2. Open `<site>/wp-admin/admin.php?page=ppcart-settings#emails` and confirm `#content_tab_emails`.
3. Click `[data-testid="ppcart-admin-email-emailtemplate-purchase-manage"]` — this is the one type
   whose modal key (`purchase`) does not match its own name — and wait for `is-open`.
4. Turn `_ppcart_email_confirmation_enable` on by clicking its `label[for=...]`; the input is
   `display: none`, so `check()` cannot be used.
5. Save from inside the modal and wait for the `settings-updated=true` redirect.
6. Assert the "Purchase Confirmation" row status dot renders `is-enabled` before anything is fired.
7. Empty the Mailpit mailbox.
8. POST the fixtures trigger `order_status` for the seeded order with status `paid` and a unique
   `@example.invalid` recipient.

## Expected result

1. A Mailpit message addressed to that recipient arrives within the wait window.
2. Its subject is not empty.

## Edge cases

- Attachment behaviour is deliberately out of scope here; EM-012 covers the invoice PDF path.
- Runs serially — all settings tabs share one form posting to `options.php`.
