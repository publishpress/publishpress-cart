# Security: an unsigned browser GET is never logged as a rejected request

## Scenario

The webhook endpoint can be hit by random browsers and crawlers. Logging those would let an unauthenticated visitor flood the log with simple browser visits, a log-spam and disk-fill risk. This security control verifies that a missing-signature rejection from a plain browser visit is silently dropped, not written.

## Steps

1. Start with the webhook log reset.
2. Simulate a plain browser visit to the webhook endpoint with no signature and no JSON content type.
3. Attempt to record a missing-signature rejection for that request.
4. Read the log entries back.

## Expected result

No entries are written; a plain browser visit is refused before anything is recorded.

## Edge cases

- Requests without a webhook-shaped content type and without a signature are also refused even when they are POSTs, blocking generic noise.
