# Failed Sync Stores A Backoff Timestamp

## Scenario

To avoid hammering Stripe on repeated failures, a failed sync must schedule a future "do not retry before" time. This case verifies that recording a sync failure stores a non-empty backoff time on the subscription.

## Steps

1. Start with an active Stripe subscription.
2. Record a sync failure for it.

## Expected result

The subscription's backoff time is set to a non-empty value, representing the time before which reconciliation should skip this record.

## Edge cases

- A backoff time must be written even on the very first failure, not only after repeated failures.
