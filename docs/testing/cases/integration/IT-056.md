# A generic "handled" row is suppressed once the event already has a final row

## Scenario

A single Stripe event can pass through several handlers in one request, but the log should record only one meaningful final outcome per event rather than a noisy trailing "handled" entry. This verifies that after a specific final outcome is written for an event, a later generic "handled" outcome for the same event is suppressed.

## Steps

1. Start with the webhook log reset.
2. For one event, record a specific final outcome (a "not matched" result).
3. For the same event, record a generic "handled" outcome.
4. Count the log entries.

## Expected result

Exactly one entry exists. The first specific outcome marks the event's final result for the request, so the later generic "handled" outcome is skipped because the event already has a final entry.

## Edge cases

- The de-duplication is scoped to a single request and keyed by the event; the generic follow-up outcomes are suppressed, not the original final outcome.
