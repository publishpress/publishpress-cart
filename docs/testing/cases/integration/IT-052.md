# Log entry preserves the Stripe event id and the normalized handling status

## Scenario

Each log entry identifies which Stripe event it describes and what the handler decided. This verifies the entry keeps the source event's id and the handling status, so operators can correlate an entry with a specific Stripe event and outcome.

## Steps

1. Start with the webhook log reset.
2. Record a webhook outcome for a sample event with a known event id and a "not matched" status.
3. Read the first log entry back.

## Expected result

The first entry carries the same event id and the same "not matched" status that were recorded, confirming both the event identity and the outcome were stored exactly.

## Edge cases

- "not matched" is an allowed status and is stored as-is, not coerced to a generic failure.
