# An order with child orders loads each child order

## Scenario

Cart stores each child order, such as an order bump, as one `order_child` row with the child's `id` and `type`. Loading the parent order must read every row as one child order. Reading only the first row and looping over its fields reaches the `type` string and stops with a fatal error, for example on the Orders list. Older or imported orders can also hold rows that are serialized strings, plain strings or arrays without an ID.

## Steps

1. Create a parent order with one child row, as Cart writes it for an order bump, and load its data and child orders.
2. Create a parent order with one valid child row, one child row stored as a serialized string, one plain string row and one row without an ID.
3. Load the order data and its child orders.

## Expected result

The single child row loads as one child order. In the second order, the valid row and the serialized row load as child orders. The rows without an order ID are skipped. No error occurs.

## Edge cases

- A bare numeric row still loads as a child order ID.
