# Order built from a shopping cart

## Scenario

Cart checkout builds one order from the priced cart. The order must load again
as a cart order. Work that runs for each product reads one context for each
item.

## Steps

1. Build an order from a cart with two products and the customer fields. Build
   an order from a cart with one line.
2. Store the two-product order. Load it again as a `PPCart_Order` and through
   `ppcart_setup_order()`. Load a Buy now order the same way.
3. Add a free item to the cart, store the order, and read its item contexts.
4. Build an order while a `ppcart_shopping_cart_order_loaded` filter lowers the
   first item to 19.00. Build it again while the filter returns another order
   object.
5. Store a cart order without item rows and read its items.

## Expected result

The order has one main item for each line with the server price. The total is
88.00, the sum of the items. It has the customer fields and the name "Writer
Toolkit + 1 more". The one-line cart gives the product name alone. After the
store, the checkout type is `cart` and no product ID is stored. Both items and
the paid cart lines come back. `ppcart_setup_order()` gives a one-time plan with
the option `cart`, the order name, and the order total. Each main item gives one
context with its own product, plan, amount, and quantity, and with the ID of
the parent order. With the filter, the total is 78.00, because the totals are
computed after the filter.

## Edge cases

- The order has no bumps, no coupon, and no custom fields.
- A Buy now order is not a cart order and has no cart plan.
- A free item gives a context too. An order ID of 0 gives no context.
- A filter that returns another object is reported as incorrect usage and
  ignored.
- `ppcart_charge_amount` receives no product.
- A cart order whose item rows are missing shows no item. No item is built for
  product 0.
