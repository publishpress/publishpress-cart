# Stored leftover report schedule migrates onto canonical cron recurrence

## Scenario

Sites that stored two-letter report-schedule values must keep sending summary
emails on the same cadence after the WP.org prefix rename. Registration on
`init` rewrites the option and reschedules WordPress cron with `ppcart_*`.

## Steps

1. Store leftover daily in `ppcart_report_schedule` and call
   `ppcart_register_report_schedule_event()`.
2. Store leftover none after a canonical daily event exists, then register
   again.

## Expected result

- Option becomes `ppcart_daily`. The `ppcart_email_schedule_hook` event
  recurrence is `ppcart_daily`.
- Leftover none becomes `ppcart_none` and the hook is unscheduled.

## Edge cases

- Canonical `ppcart_daily` already stored does not change the option value.
