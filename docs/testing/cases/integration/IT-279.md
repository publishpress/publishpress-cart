# Product setup defaults pay options and button text for checkout templates

## Scenario

`ppcart_setup_product()` builds the checkout product object that payment-plan
and submit-button templates read. Products with no plan/button meta, or with
canonical `_ppcart_*` keys only, must still produce an array of `pay_options`
and a `button_text` string so preview/checkout does not emit PHP 8 warnings.

## Steps

1. Create a `ppcart_product` with no `_sc_pay_options`, `_ppcart_pay_options`,
   `_sc_button_text`, or `_ppcart_button_text`. Call `ppcart_setup_product()`.
2. Create a product that stores plans and button text only under `_ppcart_*`
   keys. Call `ppcart_setup_product()`.
3. Create a product whose `_sc_pay_options` value is null. Call
   `ppcart_setup_product()`, then render `ppcart_payment_plan_options()` and
   the submit-button template while collecting PHP warnings.

## Expected result

1. `pay_options` is `[]` and `button_text` is `Order Now`.
2. Canonical `_ppcart_*` values appear as `pay_options` and `button_text` on
   the object.
3. `pay_options` is an array. Rendering does not emit a `foreach()` type
   warning or an undefined `button_text` property warning.

## Edge cases

- `_ppcart_*` keys win when both `_sc_*` and `_ppcart_*` exist (covered by
  step 2 using canonical keys only).
- A `ppcart_checkout_form_pay_options` filter that returns null is coerced to
  `[]` in the plan and selected-plan templates.
