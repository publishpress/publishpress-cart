# Canonical order posts store prefixed post_status and dual-read legacy paid

## Scenario

New Cart orders write `wp_posts.post_status` as `ppcart_paid` while `_ppcart_status`
meta stays `paid`. WP_Query for logical `paid` must still find both prefixed and
legacy rows. Plugin upgrade rewrites leftover unprefixed status on canonical
order CPTs only.

## Steps

1. `wp_insert_post` a `ppcart_order` with `post_status` `paid` and `_ppcart_status` meta `paid`.
2. Query orders with `post_status` `paid`.
3. Insert a canonical order, then `$wpdb->update` its `post_status` back to `paid`, and query again.
4. Call `PPCart_Post_Status_Sync::migrate_stored_statuses()` on that leftover row.

## Expected result

- Stored `post_status` is `ppcart_paid`. Meta `_ppcart_status` is `paid`.
- The `paid` query returns the new order.
- The raw leftover `paid` row is still returned by the same query.
- After migrate, that row's `post_status` is `ppcart_paid`.

## Edge cases

- Leftover `sc_order` rows are not rewritten by Cart upgrade.
