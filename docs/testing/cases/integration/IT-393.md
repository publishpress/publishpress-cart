# Accepting a Stripe upsell charges once and records the child order

## Scenario

After a Stripe purchase, the customer accepts a one-time upsell offer. The
offer page posts to the public `ppcart_process_upsell` AJAX route, which Free
registers on the checkout controller.

## Steps

1. Create a paid Stripe parent order with a remembered payment method.
2. Provide a one-time upsell child order through `ppcart_order_child_of`.
3. Call the `ppcart_process_upsell` AJAX route with a valid upsell nonce and
   Stripe mocked at the SDK HTTP client.
4. Call the route a second time for the same parent order and offer.

## Expected result

The route responds with the child order id. The child order is stored as paid
with the PaymentIntent id as its transaction id. The PaymentIntent charges the
parent order's payment method. Both calls send the same Stripe idempotency key,
so a retry replays the first charge instead of charging again.

## Edge cases

- Recording the child order runs after the Stripe call and outside its error
  handling, so a storage failure is never reported as a payment failure.
