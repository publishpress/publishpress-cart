# Security: rejected-request logging never persists the raw request body

## Scenario

A rejected webhook payload may contain sensitive or attacker-controlled data; storing it would create a privacy leak and a stored-data attack surface. This security control verifies that a logged rejection records only safe metadata — the reason, request method, content length, and a hashed client address — and never the raw body.

## Steps

1. Start with the webhook log reset.
2. Simulate a webhook-shaped JSON POST that is missing its signature.
3. Record a missing-signature rejection for that request.
4. Inspect the first entry's context.

## Expected result

The entry's context does not include the request body. It contains only the rejection reason, the request method, the content length, and a hashed client address — the raw request body is never captured.

## Edge cases

- The client address is stored only as a salted hash, never as a plaintext address.
