# Data Guard Allows Order Writes Inside A Sync Context

## Scenario

When PublishPress Cart itself is applying changes received from Stripe (for example, processing a webhook), those writes must be permitted even though they target Stripe-owned fields. Inside an authorized sync, the data guard must let order status and transaction updates through unchanged. This is the inverse of the outside-sync preservation behavior.

## Steps

1. Start with a Stripe order that has a recorded charge.
2. Change the order: set it to refunded and change the recorded transaction.
3. Run the data guard on the order from inside an authorized Stripe sync.

## Expected result

Because the guard runs inside a sync, the new values are kept: the order is refunded and the recorded transaction is the new charge. No restoration to the original charge occurs.

## Edge cases

- Mirrors IT-018 with the same starting order but inside an authorized sync, isolating the sync boundary as the sole reason the write is allowed.
