# Releasing the dedupe gate lets a not-yet-applied event be retried

## Scenario

If a webhook is recorded by the dedupe gate but its handling could not be completed, the event must be re-processable. Releasing the gate clears the event's record so a later gate check treats the event as new again, enabling a clean retry.

## Steps

1. Start with a Stripe event carrying a known event id.
2. Run the event through the dedupe gate so the event is recorded.
3. Release the gate for that event to clear the record.
4. Run the event through the dedupe gate again.
5. Check whether the event is allowed to process.

## Expected result

After the release, the gate allows the event again, treating it as unseen and confirming the release cleared the prior record.

## Edge cases

- Releasing an event that was never recorded is harmless and still leaves the gate open for that event.
