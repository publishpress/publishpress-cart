# Checkout fields declare autocomplete purpose

## Scenario

A checkout renders contact and address fields.

## Steps

1. Give the product a saved checkout field configuration (labels, sizes, required flags) for every contact and address field.
2. Render the contact fields with `ppcart_do_checkoutform_fields()`.
3. Render the address fields with `ppcart_address_fields()`.
4. Pass a select with `autocomplete` through the frontend kses allow-list.

## Expected result

First name, last name, email, phone, company, country, address lines, city, state and postcode carry `given-name`, `family-name`, `email`, `tel`, `organization`, `country`, `address-line1`, `address-line2`, `address-level2`, `address-level1` and `postal-code`. The tokens survive the product field configuration. Kses keeps `autocomplete` on selects.

## Edge cases

Fields added through filters without an `autocomplete` key render no `autocomplete` attribute.
