# PayPal cart background sync

## Scenario

PayPal webhooks and the hourly reconciliation complete a cart order when the
browser does not come back. The parent order has no product meta, so the sync
must work from the order and its items.

## Steps

1. Place a cart order with PayPal. Send a completion webhook before the buyer
   approves the order.
2. Approve the order at PayPal and run the reconciliation. Send the webhook
   again.
3. Sync a refund of the capture two times.
4. Place a second order. Mark its PayPal order as paid and send a completion
   webhook that has no status in its body.

## Expected result

After the first webhook the order stays pending. The reconciliation reads the
approved order from PayPal, captures it, and runs the cart completion work one
time. The later webhook does not repeat that work. The refund sync reads the
refund and its capture from PayPal and marks the cart order refunded. For the
second order, the webhook reads the paid capture from PayPal and then completes
the order.

## Edge cases

- A forged completion webhook cannot pay a cart order that is not approved.
- Two runs of the refund sync record one refund entry.
- After the refund sync, each product's stock shows one decrease and the buyer
  has one purchase email.
- The parent order has no product meta in each step.
