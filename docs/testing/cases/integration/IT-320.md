# Product query-var slug does not skip checkout product setup

## Scenario

WordPress copies the product CPT query var into `$GLOBALS['ppcart_product']` as the product slug string (for example `product-1`). Checkout templates expect that global to be the object from `ppcart_setup_product()`. A truthy check treats the non-empty slug as already set up, so `checkout1.php` reads `$ppcart_product->ID` on a string. `ppcart_checkout_product_context()` must treat a non-object global as unset and hydrate from the product post ID, never from `ppcart-order`.

## Steps

1. Create a published product whose slug is `product-1`.
2. Set `$GLOBALS['ppcart_product']` to that product's `post_name` (the slug string).
3. Set the global `$post` to the product post.
4. Call `ppcart_checkout_product_context()` with the product post ID.

## Expected result

The function returns a product object whose `ID` matches the product post ID, not the slug string.

## Edge cases

- A non-empty slug is truthy, so a `($ppcart_product) ? $ppcart_product : ppcart_setup_product(...)` fallback must not be used.
- The `ppcart-order` query argument is an order ID and must not be passed into product setup.
