# Reader hydrates order/customer display context from a stored record_id

## Scenario

To avoid writing customer personal data (amount, email, name) into the on-disk log, only a local record reference is stored; the human-readable details are looked up at read time for the admin view. This verifies that an entry carrying just a record reference is filled in on read with the amount, subscription, customer email, and customer name resolved from the linked order.

## Steps

1. Start with the webhook log reset, plus an order (with a recorded amount, customer email, and customer name) linked to a subscription.
2. Record a webhook outcome that references that order.
3. Read the first entry's filled-in context.

## Expected result

When read, the context exposes the order's amount, the linked subscription, the customer email, and the customer name — all looked up from the order via the stored reference, not written into the log file.

## Edge cases

- The stored reference resolves to either an order or a subscription; the personal details are filled in only on read, keeping the log file free of customer data.
