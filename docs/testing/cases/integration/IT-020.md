# Data Guard Reverts Local Edits To A Stripe Subscription Outside Sync Context

## Scenario

A Stripe-backed subscription keeps its authoritative state in Stripe-owned fields: its status, its subscription-level status, its gateway subscription reference, and its next billing date. When code outside a sync tries to cancel or re-key the subscription locally, the data guard must restore the saved Stripe values so the subscription cannot be silently desynced from the gateway. This is the subscription counterpart to the order preservation case.

## Steps

1. Start with a Stripe subscription that has a gateway reference and a next billing date (status active).
2. Locally change the subscription: set it to canceled, change the gateway reference, and change the next billing date.
3. Run the data guard on the subscription without being inside a Stripe sync.

## Expected result

The Stripe-owned fields are restored: the subscription is active again, its gateway reference is the original, and its next billing date is the original. The local edits are discarded.

## Edge cases

- Both status fields and the gateway subscription reference are preserved together, not just the lifecycle status.
- Runs outside a sync; a sync write would instead be permitted (cf. IT-019).
