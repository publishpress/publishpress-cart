# Preview REST route applies checkout block text settings

## Scenario

The block editor lets authors customize checkout labels and headings, and the preview must reflect those custom names. This case verifies that a custom heading supplied for the preview actually appears in the rendered preview rather than being ignored.

## Steps

1. Sign in as a user who is allowed to edit cart products.
2. Request a checkout preview for a configured product, supplying a custom contact info heading.

## Expected result

The rendered preview shows the supplied custom heading, confirming the custom text was applied.

## Edge cases

- Skipped if a configured product or a user allowed to edit cart products is unavailable.
