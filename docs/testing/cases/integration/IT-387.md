# Queries with canonical IN lists return the seeded rows

## Scenario

WordPress.org review rejects SQL that concatenates the output of
`ppcart_sql_in_meta_keys()`, `ppcart_sql_in_post_types()`, or
`ppcart_sql_in_post_statuses()`. Free now passes the canonical key, post type,
and status values as `$wpdb->prepare()` arguments. The queries must still
return the same rows.

## Steps

1. Seed orders, subscriptions, and products with canonical `_ppcart_*` meta.
2. Call the user phone and address lookups, the report customer search, the
   report subscription totals, the customer list, the dashboard order and plan
   totals, the Contacts page, the admin order search, and the price-format
   migration.

## Expected result

- Each lookup reads only rows of the correct post type, status, and meta key.
- Trashed orders and other post types are left out.
- Paid orders count toward totals; unpaid orders do not.
- The price-format migration changes order and subscription amounts only.
