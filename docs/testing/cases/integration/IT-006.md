# Charge Sync Routes Refunded Charges Through Refund-Log Recording

## Scenario

When the sync receives a refunded charge, it must record each individual Stripe refund in the order's refund log, keyed by the refund's identifier. This ensures refunds discovered through a charge are recorded for reporting and to avoid duplicate processing.

## Steps

1. Start with a refunded order whose refund log is empty.
2. Run a refunded Stripe charge that carries one refund through the sync.
3. Check the order's refund log.

## Expected result

The refund log now contains an entry for that refund, proving the refunded charge was routed through refund-log recording and the Stripe refund was captured under its own identifier.

## Edge cases

- The refund log is keyed by Stripe refund, so replays of the same refund would not create duplicate entries.
