# Dashboard widget registration uses canonical id only

## Scenario

Slice 23 registers the Monthly Overview widget as `ppcart_dashboard_widget`. WordPress `$wp_meta_boxes['dashboard']` must not also contain leftover `studiocart_dashboard_widget`. Compatibility Mode does not dual-register the leftover id.

## Steps

1. Load wp-admin dashboard helpers and set the current screen to `dashboard`.
2. Isolate `$wp_meta_boxes`.
3. Call `PPCart_Dashboard_Widget::register()` without constructing collaborators.
4. Assert the dashboard core context has `ppcart_dashboard_widget` and not `studiocart_dashboard_widget`.

## Expected result

The canonical widget id is registered with the widget instance `render` callback. The leftover StudioCart id is absent.

## Edge cases

- Existing user dashboard layout usermeta that hid or reordered `studiocart_dashboard_widget` does not follow the new id (hard cutover, same as slice 9 admin slugs).
- IT-214 locks the PHP class name, not this widget id.
