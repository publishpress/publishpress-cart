# Mailchimp REST client rejects invalid keys and handles PUT and 204

## Scenario

Checkout-adjacent Mailchimp sync uses `ppcart_mailchimp_api_request()`, not
`\MailchimpMarketing\ApiClient`. Invalid credentials must fail before HTTP.
Member upsert must PUT JSON to the datacenter URL. Mailchimp DELETE 204 with an
empty body must succeed as an empty object, not a parse error.

## Steps

1. Leave `_ppcart_mailchimp_api` empty. Call `ppcart_mailchimp_api_request('lists')`.
2. Store `abc123-us1`. `pre_http_request` intercepts. PUT
   `lists/{id}/members/{hash}` with `email_address` / `status`.
3. Intercept DELETE of that member path; respond `204` with an empty body.

## Expected result

1. `WP_Error` code `ppcart_mailchimp_invalid_api_key`. No HTTP.
2. Request URL is `https://us1.api.mailchimp.com/3.0/lists/{id}/members/{hash}`,
   method `PUT`, JSON body includes `email_address` and `status`. Return is the
   mocked JSON object.
3. Return is an empty `stdClass`, not `WP_Error`.

## Edge cases

- A 204 with `''` body must not hit the invalid-JSON error path.
