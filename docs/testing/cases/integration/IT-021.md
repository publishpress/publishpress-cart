# Data Guard Leaves A Non-Stripe (COD) Order Editable

## Scenario

The data guard must only protect orders whose payment is actually backed by Stripe. An order paid by Cash on Delivery is not Stripe-backed, so its status is fully merchant-controlled and the guard must leave any change untouched. This confirms the guard keys off the payment method and does not over-reach into non-Stripe orders.

## Steps

1. Start with a Cash on Delivery order (not Stripe-backed) marked paid.
2. Set the order status to paid.
3. Run the data guard on the order outside any sync.

## Expected result

The guard performs no preservation for this non-Stripe order: the status is returned exactly as set, demonstrating the value is locally editable.

## Edge cases

- The Cash on Delivery payment method is what excludes the order from guarding; the same status would be preserved on a Stripe order (cf. IT-018).
