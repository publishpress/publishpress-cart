# Settings and plan hooks fire canonical ppcart names

## Scenario

Plugin Check flags `_ppcart_*` hook names as not prefixed (publishpress/publishpress-cart#879).
Free renamed them to `ppcart_*` with no alias. `_ppcart_plan` became
`ppcart_plan_data` and `_ppcart_register_sections` became
`ppcart_register_integration_sections`, because the plain names were already
hooks with different arguments.

## Steps

1. Hook `ppcart_invoice_option_list` and build invoice fields.
2. Hook `ppcart_register_gateways` and register the payment gateway sections.
3. Hook `ppcart_register_integration_sections` and register the Integrations
   tab sections.
4. Hook a custom tab's `ppcart_{$tab}_tab_section` filter and register that tab.
5. Hook `ppcart_plan_data` and build a plan.

## Expected result

- The option-list filter changes the returned fields.
- The gateway action receives the settings object and the payment page slug.
- The integration action receives the settings object and plugin name, and the
  argument-less `ppcart_register_sections` action does not fire.
- The custom tab's extra section is registered.
- `ppcart_plan_data` receives the built plan and the pay option.
