# Actual Cart menu registration stabilizes canonical hook suffixes

## Scenario

The plugin's real menu registration keeps WordPress screen IDs canonical even
when the filterable display/menu title is `PublishPress Cart`.

## Steps

1. Create and authenticate a temporary administrator.
2. Call `PPCart_Admin_Settings::setup_plugin_options_menu()` with the display
   title `PublishPress Cart`.
3. Assert the `ppcart` parent hook base and generated dashboard/settings hooks.
4. Remove registered callbacks, restore menu globals and the original current
   user, and delete the temporary administrator.

## Expected result

`$admin_page_hooks['ppcart']` remains `ppcart`. WordPress generates
`toplevel_page_ppcart` and `ppcart_page_ppcart-settings`, matching
`PPCart_Admin_Screens` constants instead of deriving IDs from the display title.

## Edge cases

- The test starts with isolated menu globals and restores their prior values.
- The temporary administrator is deleted after restoring the original user.
- No legacy menu registration or compatibility redirect participates.
