# Shopping cart REST API

Read an empty cart through `GET /ppcart/v1/cart`. The response has the cart
shape, a valid REST nonce, and the no-store cache header. No row and no cookie
exist.

Add two lines. Prices are decimal strings from the server, and a price in the
request body is ignored. The response never holds the cart key, the user ID, or
the seen price.

Changes without a valid REST nonce are refused with 403. Reading needs no nonce.

Each cart error has its HTTP status and carries the current cart: 422 for an
ineligible product, plan, or quantity, 409 for a duplicate key, 404 for a
quantity change of a missing line, 400 for malformed input, and 403 for a
disabled cart. Removing a missing line returns 200.

The totals filter can add rows, and stored notices reach the response. A
signed-in visitor reads and changes only their own cart.

URL-encoded line keys are decoded once before PATCH and DELETE. A plan ID with
colons, a slash, and a literal percent escape still identifies the same line.
