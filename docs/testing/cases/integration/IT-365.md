# Admin mutators require object and user capabilities after nonce checks

## Scenario

Several authenticated admin and my-account mutators already verify nonces but must also enforce WordPress capabilities before writing data. Order and download-meta saves must require `edit_post` on the order. Legacy tracking notice dismiss must require `manage_options`. My-account profile AJAX must require `edit_user` on the current user so subscribers can still edit themselves.

## Steps

1. Seed a paid order with an order log entry and assign a subscriber as `post_author`.
2. Sign in as that subscriber, set the admin edit screen, and submit an order save with a valid `update-post_{id}` nonce and a new first name.
3. Sign in as a Cart Manager and repeat the save with a different first name.
4. Seed an order with a download row; sign in as a subscriber and submit download-meta save fields with a valid nonce.
5. Sign in as a subscriber and request legacy tracking notice dismiss with a valid admin referer nonce.
6. Sign in as a subscriber and submit my-account profile AJAX with a valid nonce and profile fields.

## Expected result

The subscriber cannot change order first name, download remaining counts, or dismiss meta. The Cart Manager persists the order first-name change. The subscriber profile AJAX succeeds without using `edit_users`.

## Edge cases

- The subscriber is the order `post_author` but lacks `edit_ppcart_orders`.
- Nonces are valid for the requesting user so denials are capability-driven, not CSRF misses.
