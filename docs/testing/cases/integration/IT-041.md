# Re-delivered webhook event id is rejected by the dedupe gate

## Scenario

When Stripe re-sends an event that PublishPress Cart already processed, the dedupe gate must block the second pass to prevent duplicate side effects such as double refunds or duplicate status changes. After the first pass records the event, a second attempt for the same event must be refused.

## Steps

1. Start with a Stripe event carrying a known event id.
2. Run the event through the dedupe gate a first time so the event is recorded.
3. Run the same event through the dedupe gate a second time.
4. Check whether the second pass is allowed.

## Expected result

The second pass is refused, showing the duplicate event is recognized and further processing is blocked.

## Edge cases

- The block stays in effect for as long as the event remains recorded, so any further re-delivery of the same event is likewise rejected until the gate is released.
