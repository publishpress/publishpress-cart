# Checkout offers a login when the buyer's email already has an account

## Scenario

A buyer whose email already has an account was asked to choose a new password at checkout. The order was linked to the old account and the new password was ignored. With the setting "When the buyer's email already has an account" set to "Ask the buyer to log in or reset their password", the checkout tells the buyer and offers a login instead.

## Steps

1. Set the option to ask the buyer to log in.
2. Use a product with the "Create user" integration or a password custom field.
3. Check a registered email and a new email with `ppcart_check_email`.
4. Log in with `ppcart_checkout_login`, with the right password and with a wrong one.
5. Validate the order form for a registered email with empty password and username fields.
6. Complete the order for a registered email without logging in.

## Expected result

- `ppcart_check_email` answers `{ exists: true }` only for a registered email, and nothing else about the account.
- It answers `{ exists: false }` when the setting is off, for a product that creates no account, and over the rate limit.
- `ppcart_checkout_login` logs the buyer in. Every failure gives the same message and runs `wp_login_failed`.
- The password and username fields are not required for a registered email.
- The order links to the existing account, the account keeps its old password, and the buyer is not logged in automatically.
- The checkout form marks the email field and renders the notice in an `aria-live="polite"` region. Account fields carry `data-ppcart-account-field`.

## Edge cases

- A request without a valid checkout nonce gets an error and no account answer.
- With the setting off, the form renders no notice and no email marker.
