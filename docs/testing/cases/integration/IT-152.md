# Preview REST route returns rendered checkout HTML

## Scenario

Beyond authorizing the request, the preview endpoint must return the actual rendered checkout so the block editor can display it. This case verifies the preview response contains a real, non-empty rendered checkout for the requested product.

## Steps

1. Sign in as a user who is allowed to edit cart products.
2. Request a checkout preview for a configured product.

## Expected result

The preview response contains the rendered checkout form for the product, not an empty result.

## Edge cases

- Skipped if a configured product or a user allowed to edit cart products is unavailable.
