# Admin hooks register canonical method callbacks on live CPT tags

## Scenario

Slice 20 keeps CPT-derived hook **tags** on `ppcart_live_post_type()` / `ppcart_query_post_types()` and moves only the callback methods. First-party must not register leftover method names such as `save_post_sc_order` or `set_custom_edit_sc_*_columns`. Listed leftover PHP parameters on loaded classes use `$ppcart_*` names.

## Steps

1. After plugin bootstrap, inspect callbacks on `save_post_{live_order}`, `manage_{live_cpt}_posts_columns`, `manage_{live_cpt}_posts_custom_column`, and `admin_init`.
2. Assert owning classes expose the canonical methods and not leftover `sc_` names.
3. Assert `PPCart_Files::update_order_downloads` is registered on `save_post_{live_order}` at priority 99.
4. Reflect leftover-renamed parameters on settings, Kit, Cancel Subscription, and `ppcart_do_integrations()`.

## Expected result

- `save_post_{live_order}` includes `save_post_order`, not `save_post_sc_order`.
- List-table column callbacks use `set_custom_edit_product_columns` / `custom_order_column` / subscription equivalents, not leftover `*_sc_*` names.
- `admin_init` includes `register_importers`, not `register_sc_importers`.
- Files registers `update_order_downloads` on the live order save hook at priority 99.
- `PPCart_Admin`, list controller, metabox option sources, settings, and order metaboxes expose canonical methods only.
- Settings/Kit/Cancel Subscription/`ppcart_do_integrations()` parameters are `$ppcart_tab(s)`, `$ppcart_product_id`, and `$ppcart_mail_*`.

## Edge cases

- Live CPT slugs stay leftover until Data migration completes; this case uses `ppcart_live_post_type()`, not a hardcoded `sc_order` tag.
- Compatibility Mode may still map leftover hook **tags**; leftover **method** names are not aliased.
