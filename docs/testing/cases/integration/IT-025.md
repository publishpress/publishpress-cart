# Resource event meta is recorded under canonical post-meta keys

## Scenario

When PublishPress Cart processes a Stripe event for a subscription, it records the last seen event so future webhooks can be deduplicated and audited. The plugin must save that event's identifier, its type, and a sync timestamp on the subscription. This case verifies the recorded values for an incoming event.

## Steps

1. Start with a Stripe subscription.
2. Process an incoming "subscription updated" event for it.
3. Read back what the subscription recorded.

## Expected result

The subscription records the event's identifier, the event type "subscription updated", and a non-empty sync timestamp.

## Edge cases

- The sync timestamp is only checked to be non-empty rather than a fixed value, since it reflects the current time.
- All three values are stored together, confirming event tracking is recorded on the subscription.
