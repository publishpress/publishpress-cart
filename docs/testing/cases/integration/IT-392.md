# Order bulk actions require per-object edit capability

## Scenario

The order and subscription list-table bulk handler receives object IDs after
WordPress verifies the bulk-action nonce. Each object must also pass its own
`edit_post` capability check before Cart changes status, cancels or resumes a
subscription, or synchronizes it with Stripe.

## Steps

1. Create an order and select a subscriber who cannot edit it.
2. Run the paid-status bulk action and observe the order update behavior.
3. Create a Stripe-backed subscription and select a subscriber who cannot edit
   it.
4. Run the Stripe-sync bulk action and inspect its result query arguments.

## Expected result

The denied order is not updated and does not fire `ppcart_order_updated`. The
denied subscription is not sent to the Stripe sync layer and is not counted as
a failed sync.

## Edge cases

- The core bulk-action nonce does not replace the per-object capability check.
- Capability checks run before post-type inspection and every mutation path.
