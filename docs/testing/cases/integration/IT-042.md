# Dedupe gate records event under the ppcart_stripe_evt_ transient prefix

## Scenario

The dedupe gate remembers processed events using a short-lived stored marker. To avoid clashing with other stored values, each event is recorded under a dedicated plugin namespace combined with the Stripe event id. This case confirms the gate actually records a marker for the event so the de-duplication behavior is dependable.

## Steps

1. Start with a Stripe event carrying a known event id.
2. Run the event through the dedupe gate once so the event is recorded.
3. Look for the stored marker that corresponds to that event.

## Expected result

A stored marker for the event exists after the gate runs, confirming the event was recorded under its own namespaced entry.

## Edge cases

- The marker is keyed by the event id, so each distinct event gets its own independent record.
