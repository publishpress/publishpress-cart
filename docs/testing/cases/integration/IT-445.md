# Cart checkout order and payment

Submit the cart checkout with two products and Stripe. One pending order is
stored with both items. One PaymentIntent is created for the order total, with
the cart metadata, the order description, and the Stripe Connect fee. A product
ID or an amount in the request changes nothing.

The order becomes paid only when Stripe reports a succeeded payment that names
that order. A wrong token, another order's payment, or a Buy now order is
refused. A second confirmation does not run the completion work again.

Change a price after the form loaded and submit. The request is refused with
the new cart, and no order or payment exists. The next submit with the new
revision pays the new total. A second submit of the same form is refused.

Missing fields, an unknown pay method, and a purchase limit are refused before
the cart is claimed. A gateway error leaves a pending order and no charge.

A free cart is paid without a gateway. Cash on delivery stores a pending order
and empties the cart. Both routes need a REST nonce and an enabled cart.
