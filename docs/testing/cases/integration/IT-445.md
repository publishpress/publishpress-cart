# Shopping cart rules and storage

## Scenario

The cart stores the lines of one visitor in its own table. Each read takes the
prices from the server, repairs the lines, and records what changed as notices.

## Steps

1. Run the upgrade routine two times. Read the cart table and the cleanup
   schedule.
2. Read a cart before any add. Add a plan whose ID contains a colon.
3. Add the same key again. Add a second plan of the same product. Remove a key
   that is not in the cart.
4. Add a hidden, an unpublished, a recurring, an aliased, and an unknown offer.
   Add with the cart turned off. Add a new key to a full cart.
5. Compare the unit price of a line with the initial payment of its plan.
6. Change the price of a plan in the cart and read the cart two times. Hide a
   product in the cart and read the cart.
7. Set a quantity of 2. Raise the limit to 3 with
   `ppcart_shopping_cart_item_max_quantity`, set a quantity of 3, then remove
   the filter and read the cart.
8. Store an extension meta value before and after the first add. Store a
   reserved meta key.
9. Let a cart expire and run the cleanup. Read a cart with the cart key of
   another owner.

## Expected result

The table has the plain prefixed name, the `revision` column, and a unique cart
key. The daily cleanup is scheduled, and deactivation removes the schedule.
Before the first add there is no row and no cart cookie. The first add stores
the IDs, quantity 1, the seen price, and a UTC time with microseconds, and puts
the cart key in the cookie. The duplicate add is refused and the cart keeps one
line. The second plan of the product is a second line. The unit price equals the
initial payment, the value that Buy now charges. After the price change, the
next read charges the new price, stores one price notice, and moves the seen
price. A later read adds nothing. The line of the hidden product is removed
with a removed notice.

## Edge cases

- The remove of a missing key succeeds without a write.
- Each offer that is not eligible is refused with its error code and creates no
  cart. A cart that is off refuses each add. A full cart refuses a new key.
- A cart that becomes empty drops the cart cookie and keeps the row.
- Quantity accepts only 1 until a filter raises the limit. When the limit goes
  down, the next read lowers the quantity and marks the cart as changed.
- Extension meta is stored on an existing cart only. It creates no row.
  Reserved keys are refused.
- An expired cart is not read, and the cleanup deletes it.
- A cart key never opens the cart of another owner, for a guest or for a user.
