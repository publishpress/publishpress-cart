# Leftover sc/v1 REST routes stay unregistered

## Scenario

Free Gutenberg registers checkout and account block routes under `publishpress-cart/v1`. Leftover `sc/v1` is a hard cutover: it stays unregistered with Compatibility Mode off and on. Free does not dual-register leftover developer REST.

## Steps

1. After `rest_api_init`, assert Gutenberg routes exist under `/publishpress-cart/v1/...`.
2. With Compatibility Mode off, assert no registered route key starts with `/sc/v1`.
3. Enable Compatibility Mode, fire `rest_api_init` again, and assert leftover `sc/v1` is still absent while canonical Gutenberg routes remain.

## Expected result

Canonical Gutenberg REST routes are registered. No `/sc/v1` routes exist in either Compatibility Mode state.

## Edge cases

- Pro developer REST cutover to `publishpress-cart/v1` is later; this case only locks Free.
- WordPress core `/wp/v2/...` routes are unrelated and must remain.
