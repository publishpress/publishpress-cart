# Security: repeated rejected requests are rate-limited to one entry per window

## Scenario

Without throttling, an attacker could repeatedly hit the endpoint to inflate the log and exhaust disk. This security control verifies that consecutive identical rejections from the same source within a short window produce only a single log entry.

## Steps

1. Start with the webhook log reset.
2. Simulate a webhook-shaped JSON POST that is missing its signature.
3. Record a missing-signature rejection for that request twice in a row.
4. Count the log entries.

## Expected result

Exactly one entry is written. The first rejection sets a short-lived suppression for that reason and source, so the second rejection within the window is suppressed.

## Edge cases

- The rate limit is scoped per reason and per source, so distinct reasons or sources are still logged independently.
