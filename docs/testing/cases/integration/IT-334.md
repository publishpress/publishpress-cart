# Admin bulk actions register and redirect with canonical ppcart slugs

## Scenario

Slice 32 registers order/subscription list-table bulk actions as
`ppcart_make_*` / `ppcart_sync_stripe`. The handler receives that dropdown slug
as `$doaction` and writes `bulk_ppcart_*` redirect query args. The Stripe sync
admin notice reads only the canonical GET keys. Empty `$object_ids` so Stripe
never runs. Hard cutover; leftover slugs are absent.

## Steps

1. Call `order_bulk_action` / `subscription_bulk_action` and assert canonical
   keys are present and leftover `sc_make_*` / `sc_sync_stripe` keys are absent.
2. Call `bulk_action_handler( $redirect, 'ppcart_sync_stripe', [] )` and assert
   the redirect contains `bulk_ppcart_sync_stripe`.
3. Call `bulk_action_handler( $redirect, 'ppcart_make_paid', [] )` and assert
   the redirect contains `bulk_ppcart_make_paid`.
4. Set `$_GET['bulk_ppcart_sync_stripe']` and assert `sync_stripe_bulk_notice`
   prints. Set leftover `$_GET['bulk_sc_sync_stripe']` and assert it does not.

## Expected result

Dropdown keys and redirect query args use only canonical `ppcart_*` /
`bulk_ppcart_*` names. The sync notice prints for the canonical GET key and
stays silent for the leftover key.

## Edge cases

- Comparing `$doaction` to a `bulk_*` string would make the paid-status
  redirect miss `bulk_ppcart_make_paid` (this case catches that).
- Empty `$object_ids` still adds the count/synced query arg (`0`).
- Bookmarked leftover GET `bulk_sc_sync_stripe*` no longer shows the notice.
