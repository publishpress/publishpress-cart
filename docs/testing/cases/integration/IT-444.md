# Cart order completion

Pay a cart order with two products while an extension replays the status hook
for each item of a `main` order. `ppcart_order_complete` fires once, and the
after-primary hook gets the order type `cart`, so the extension does not replay.
Integrations, product notifications, and stock run once for each item. One
purchase email goes to the buyer and lists both items, even when a product
turns its purchase email off. The download grants exist for both products. The
paid lines leave the cart and a line added after the checkout stays. A second
save with the same status does nothing.

A cash on delivery order runs the pending work for each item and empties the
cart. A refund with restock revokes the download of each item and restores the
stock of each item. A Buy now order with an item of another product still gets
the order type `main` and its replay.

The data of the order lists every item in the merge tags. The context of one
item lists that item. Revenue is split by product from the item totals. The
customer-bought-product shortcode finds a product, and a plan when asked, in a
paid cart order.
