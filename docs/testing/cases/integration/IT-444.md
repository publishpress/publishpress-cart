# Cart settings and page creation

## Scenario

The Shop & Cart tab saves each field through its native settings sanitizer. The
runtime reads the same fields as typed settings. A merchant can create the
missing Shop, Cart, and Checkout pages more than one time without a duplicate.

## Steps

1. Read the typed settings before any save.
2. Save every Shop & Cart field with a valid value. Read the stored options and
   the typed settings.
3. Save an unknown choice for the two select fields, a post ID that is not a
   page, a negative lifetime, a lifetime that is an array, a `javascript:` URL,
   and a message with a script tag.
4. Read the checkout field list. Turn on phone, address, and terms. Add the
   terms URL. Add a field through `ppcart_shopping_cart_checkout_fields`.
5. Create the missing pages two times. Move the created Cart page to the trash
   and create the missing pages again. Set a merchant page as the Shop page and
   create the missing pages again.
6. Call the admin page action with a GET request, as a subscriber, and with an
   invalid nonce.
7. Read the confirmation of an order for each confirmation type.

## Expected result

The defaults are an enabled cart, the Mini Cart after an add, a lifetime of 7
days, and no page URL. Each stored option equals the saved value, and the typed
settings return those values. The first page run creates the Shop, Cart, and
Checkout pages with their blocks. The Checkout block has the source Cart and no
other attribute. The second run creates no page. After the trash,
only the Cart page is created again. The merchant page is skipped and keeps its
content. The confirmation message has the customer's name. The checkout page URL
and the confirmation page URL carry the order ID and the order token. The
redirect URL is returned as saved.

## Edge cases

- An unknown choice falls back to the declared default. A post that is not a
  page is stored as 0. A negative lifetime becomes 1 day, and an array becomes
  the default.
- A `javascript:` URL is stored as an empty value. The script tag is removed
  from the message and the safe HTML stays.
- The terms field shows only when a terms URL is set. Phone and the second
  address line are optional.
- The admin action refuses a GET request, a user without the capability, and an
  invalid nonce. It creates no page in those cases.
