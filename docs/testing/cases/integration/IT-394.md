# MCP native integration mappings

## Scenario

An authorized merchant maps a declared checkout field to a configured integration.

## Steps

1. Discover native services, fields, mapping sources and revision through the released Adapter.
2. Preview and save a Kit rule using a declared custom field.
3. Run the native handler with isolated order data and intercept HTTP delivery.
4. Submit an unknown or secret selector and inspect native storage.
5. Remove the field or change its type to password before resolving it again.

## Expected result

Preview makes no HTTP calls. Save uses native map lines. Native delivery contains only the selected declared value. Invalid mappings fail without writes; removed/password fields never fall back to arbitrary metadata.

## Edge cases

List values retain their JSON type. Password/secret/token field identifiers and arbitrary order metadata are unavailable.
