# Account Tab Script Normalizes Hash Tab Links

## Scenario

The public account tab behavior works out which panel to show from the tab link's hash target rather than its full address. That only works when every rendered tab link is an in-page hash link whose target is a panel in the same account area, so clicking a tab link reliably reveals the matching panel.

## Steps

1. Sign in as a customer.
2. Render an account page whose navigation holds an Orders tab and a My Profile tab.
3. Inspect each tab link and the panel its hash points at.

## Expected result

- Each tab link is a plain `#panel-id` hash link.
- The hash of each tab link matches exactly one rendered tab panel.
- Each tab link controls the panel its hash points at, and that panel is labelled by the tab.
- The tabs point at the Orders and My Profile panels, in that order.

## Edge cases

- The check is skipped when a temporary customer account cannot be created.
