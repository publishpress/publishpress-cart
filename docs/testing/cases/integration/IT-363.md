# Subscription sync AJAX requires store and subscription edit capabilities

## Scenario

The manual Stripe subscription sync AJAX action receives a Stripe subscription ID and can update local subscription and order records. A logged-in user with a valid nonce must not be able to sync subscriptions unless they can manage Cart and edit the resolved subscription post. The leftover GET `ppcart-subscription-sync` query arg must not run that sync.

## Steps

1. Seed a Cart subscription with a known Stripe subscription ID.
2. Sign in as an author and submit the sync AJAX request with a valid nonce.
3. Sign in as an author with only the Cart manager option capability and submit the same request.
4. Sign in as a Cart Manager and submit the same request without Stripe keys configured.
5. Sign in as an author who can `edit_post` the subscription but lacks `ppcart_manager_option` and `manage_options`, then submit the same request.
6. Sign in as a Cart Manager and load the subscription info metabox with `ppcart-subscription-sync` in the query string.

## Expected result

The author requests return `Unauthorized access.` The Cart Manager clears both capability gates and reaches the sync layer, which returns `Stripe secret key missing.` before any Stripe API call is attempted. The subscription-editor-without-store-cap request also returns `Unauthorized access.` The leftover GET query arg does not change local subscription status.

## Edge cases

- The nonce is minted as the requesting user.
- The subscription exists before low-privilege users submit the request, so denials cannot be confused with lookup misses.
- The CPT-edit-only user can `edit_post` the subscription, so a store-level denial cannot be confused with an object-cap miss.
