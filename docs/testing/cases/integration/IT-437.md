# Shopping cart rules and storage

Run the upgrade routine twice and read the cart table. It has the plain prefixed
name, the `revision` column, and a unique cart key. The daily cleanup is
scheduled, and deactivation removes the schedule.

Read a cart before any add. No row and no cart cookie exist. Add a plan whose ID
contains a colon. The row stores IDs, quantity 1, the seen price, and a UTC time
with microseconds. The cart key is in the cookie.

Add the same key again. The cart refuses it and keeps one line. A second plan of
the same product is a second line. Removing a missing key succeeds without a write.

Hidden, unpublished, recurring, aliased, and unknown offers are refused with
their error codes and create no cart. A disabled cart refuses every add. A full
cart refuses a new key.

The unit price equals the plan's initial payment, the value Buy now charges.

Change a plan price after the add. The next read charges the new price, stores
one price notice, and moves the seen price. A later read repeats nothing. Hide a
product in the cart. The next read removes its line and stores a removed notice.
An emptied cart drops the cart cookie and keeps the row.

Quantity accepts only 1 until a filter raises the limit. Extension meta is
stored on an existing cart, and reserved keys are refused.

An expired cart is not read, and the cleanup deletes it. A cart key never opens
the cart of another owner, for a guest or for another user.
