# Mini Cart and live Shop forms

## Scenario

The Mini Cart is on pages that a page cache stores, so its server output must
not depend on the visitor. The Shop forms must work with and without
JavaScript.

## Steps

1. Render the Mini Cart through its block and its shortcode, with different
   attributes and with a count cookie set. Render it with the cart turned off.
2. Add a plan whose ID contains a colon. Render the Shop.
3. Send the add form by POST without a valid operation nonce.
4. Send a valid add for each After add to cart setting. Send the same add
   again. Send the remove form with its own nonce.
5. Request the drawer fragment for a cart with a changed price. Request a
   fragment name that does not exist.

## Expected result

The block and the shortcode give the same cacheable shell, and no row is
created. The attributes control the link, the badge, and the style tokens. The
Shop shows a live submit button and marks only the added plan as in the cart.
Another plan of the product stays available. A valid add takes the server price.
It redirects to the Cart page for the Mini Cart setting and the Cart setting,
and to the Checkout page for the Checkout setting. The remove form removes the
line. The drawer fragment shows escaped names, the current totals, the stored
price notice, remove forms with a nonce, and the extension slot with the priced
cart.

## Edge cases

- A cart that is off renders no Mini Cart.
- The count cookie cannot change the server output.
- A POST without a valid operation nonce fails without a write.
- A duplicate add keeps one line.
- An unknown fragment name gives no output.
