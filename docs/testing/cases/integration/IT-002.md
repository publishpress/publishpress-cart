# Paid Charge Sync Still Stores When Stored Id Differs From Charge Id

## Scenario

An order may have been recorded against the Stripe payment intent before the final charge was known. When a "charge succeeded" sync runs for an order that is already paid but whose recorded transaction does not match the incoming charge, the sync must not skip the update — it must still record the new charge so the order references the authoritative charge.

## Steps

1. Start with a paid order whose recorded transaction is the earlier payment intent rather than the final charge.
2. Run the matching Stripe charge through the sync.
3. Check the order's recorded transaction.

## Expected result

The order's recorded transaction is updated from the payment intent to the charge, confirming the "already paid" shortcut does not block an update when the recorded reference has changed.

## Edge cases

- Contrast with IT-001, where a matching reference skips the update; here the differing reference is what forces it to be saved.
