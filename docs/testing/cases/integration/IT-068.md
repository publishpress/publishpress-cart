# Reader is resilient to corrupt JSON lines and surfaces a placeholder row

## Scenario

A log file could contain a truncated or corrupt entry, for example from a partial write or disk issue. Reading the log must not fail or abort; it should degrade gracefully so the rest of the log stays viewable. This verifies that an unreadable entry yields a safe placeholder instead of breaking the read.

## Steps

1. Start with the webhook log reset and pointed at a log file containing a malformed entry.
2. Read the log entries back.

## Expected result

Reading the log returns at least one entry, and the first one is a placeholder marked as an invalid log entry, confirming corrupt entries are substituted rather than causing a failure.

## Edge cases

- Blank lines are skipped entirely; only non-empty entries that cannot be parsed become placeholders.
