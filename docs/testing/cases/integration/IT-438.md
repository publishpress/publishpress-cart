# Shopping cart concurrency and merge

## Scenario

Two requests can write one cart at the same time. Each write is a
compare-and-swap on the revision of the row, so no committed line is lost. The
checkout claim and the login merge use the same rule.

## Steps

1. Start a write on a cart row. Before it commits, commit a different line from
   a second writer on the same row.
2. Repeat with two writers that add the same key, with a remove that races an
   add, and with a write that misses the revision three times.
3. Claim checkout with the revision that the buyer saw. Then submit the same
   form again, a form that is older than an add in another tab, and a form
   whose cart the claim had to repair. Let two submits pass the gate together.
4. Sign in with a guest cart and a user cart that share one key. Merge again.
   Insert the guest row again and merge a third time.
5. Start a login merge. After the merge reads the guest row and before it
   deletes that row, commit one more line from a guest request. Then let a
   guest write land in each of the three tries of a merge.
6. Sign in as a user without a cart. Make a signed-in request with a guest
   cookie and no login hook. Read the cart of a user who has two rows.
7. Run the completion of an order after one paid line was removed and added
   again and another line was added later. Run the completion again.

## Expected result

The first write misses the revision, loads the row again, and replays its
operation. Both lines stay, and the revision counts each commit. The checkout
claim succeeds one time. In the login merge the user line wins on the shared
key, the other guest lines are appended, the guest row is deleted, and the
cookie points at the user row. When a guest line lands during the merge, the
delete misses the revision, the merge reads the guest row again, and the user
row gets the new line. The completion removes only the lines that the order
paid for.

## Edge cases

- Two writers that add the same key leave one line. The second writer gets the
  already-in-cart error.
- A remove that races an add commits in write order.
- After three revision misses the write returns a conflict with the stored cart.
- A second submit, an old form, and a repaired cart each return the
  cart-changed error with the current cart. Two submits that pass the gate
  together claim the cart one time.
- A second merge changes nothing. A merge that repeats after a crash between
  commit and delete adds no duplicate.
- When a guest write lands in each of three tries, the merge stops. The guest
  row and the guest cookie stay, and the next merge completes the work.
- A user without a cart takes over the guest row. A signed-in request with a
  guest cookie merges without the login hook. Two rows of one user merge into
  the oldest row.
- A line that was added again after the payment started stays in the cart. A
  repeated completion callback changes nothing.
