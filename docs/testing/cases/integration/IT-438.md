# Shopping cart concurrency and merge

Start one write on a cart row. Before it commits, a second writer commits a
different line on the same row. The first write misses the revision, loads the
row again, and replays its operation. Both lines stay, and the revision counts
each commit.

Two writers that add the same key leave one line, and the second gets the
already-in-cart error. A remove that races an add commits in write order. After
three revision misses the write returns a conflict with the stored cart.

Claim checkout with the revision the buyer saw. The claim succeeds once. A second
submit of the same form, a form that is older than an add in another tab, and a
cart that the claim had to repair all return the cart-changed error with the
current cart. Two submits that pass the gate together claim the cart once.

Sign in with a guest cart and a user cart that share one key. The user line
wins, the other guest lines are appended, the guest row is deleted, and the
cookie points at the user row. A second merge changes nothing. A merge that
repeats after a crash between commit and delete adds no duplicate.

Start a login merge. After the merge reads the guest row and before it deletes
that row, a guest request commits one more line on it. The delete misses the
revision, the merge reads the guest row again, and the user row gets the new
line. When a guest write lands in each of three tries, the merge stops, the
guest row and the guest cookie stay, and the next merge finishes the work.

A user without a cart takes over the guest row. A signed-in request with a guest
cookie merges without the login hook. Two rows of one user merge into the oldest.

Completion removes only the lines that the order paid for. A line that was added
again later stays, and a repeated callback changes nothing.
