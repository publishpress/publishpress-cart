# Each log line carries the full JSON-lines schema field set

## Scenario

The log stores one normalized record per entry, and the admin viewer and downloads rely on a stable set of fields. This verifies that a recorded entry contains every expected field rather than just the values the caller passed.

## Steps

1. Start with the webhook log reset.
2. Record a webhook outcome for a sample event.
3. Read the first log entry back.

## Expected result

The entry contains the full set of expected fields, including a numeric timestamp, a human-readable UTC time, the event type, the related object and its id, the live-mode flag, the message, the context, the event id, and the status.

## Edge cases

- The related object and its id are derived from the event payload; they are present even when the event's nested object is sparse.
