# Public enqueue localizes canonical JS objects not leftover names

## Scenario

Slice 21b registers canonical `wp_localize_script` objects on the public `ppcart` script handle. Compatibility Mode must not restore leftover `studiocart` / `sc_translate_frontend` window names.

## Steps

1. Construct `PPCart_Public_Asset_Controller` and call `enqueue_scripts()`.
2. Read `WP_Scripts` extra data for handle `ppcart`.
3. Call `ppcart_do_checkout_form_scripts()` with a coupon and read the `before` inline script.
4. Assert canonical `var ppcart` / `var ppcart_translate_frontend` / `var ppcart_currency` / `var ppcart_user` assignments and `window.ppcart_coupon`, plus the absence of leftover names.

## Expected result

- Public enqueue prints `ppcart` (with `ajax`), `ppcart_translate_frontend`, `ppcart_currency`, and `ppcart_user`.
- Coupon inline prints `window.ppcart_coupon`.
- Leftover `studiocart`, `sc_translate_frontend`, `sc_currency`, `sc_user`, and `window.sc_coupon` are absent.

## Edge cases

- `ppcart_popup` only localizes when the product shortcode renders; this case does not require that path.
- Inner keys such as `is_ppcart_checkout` are slice 45 (UT-277).
