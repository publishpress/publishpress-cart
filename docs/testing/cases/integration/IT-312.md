# Admin enqueue localizes canonical JS objects not leftover names

## Scenario

Slice 21a registers canonical `wp_localize_script` objects on admin plugin screens. Compatibility Mode must not restore leftover `sc_reg_vars` / `ncsCart*` window names.

## Steps

1. Construct `PPCart_Admin` and call `enqueue_scripts()` with the settings hook suffix, then the reports hook suffix.
2. Read `WP_Scripts` extra data for handles `ppcart`, `ppcart-settings`, `ppcart-reports`, and `ppcart-repeater`.
3. Assert canonical `var ppcart_*` / `var ppcartSettings*` / `var ppcartReports` / `var ppcartNotificationI18n` assignments and the absence of leftover `var sc_reg_vars` / `ncsCart*`.

## Expected result

- Settings enqueue prints `ppcart_reg_vars` (with `ajax_url`, not `sc_ajax_url`), `ppcart_translate_backend`, `ppcart_admin_i18n`, `ppcartSettingsI18n`, and `ppcartNotificationI18n`.
- Reports enqueue prints `ppcartReports`.
- Leftover `sc_reg_vars`, `sc_translate_backend`, `sc_admin_i18n`, `ncsCartReports`, `ncsCartSettingsI18n`, and `ncsCartNotificationI18n` are absent.

## Edge cases

- Mailchimp `ppcart_mc_tags` / `ppcart_mc_groups` only localize when those options exist; this case does not require them.
