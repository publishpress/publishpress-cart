# Reconciliation Query Filters On Backoff Metadata

## Scenario

Subscriptions that recently failed carry a backoff time and must be excluded from reconciliation until that time passes. This case inspects the lookup that reconciliation builds and verifies a separate backoff filter is present.

## Steps

1. Trigger reconciliation and capture the lookup it builds.
2. Inspect the lookup for a backoff filter.

## Expected result

The lookup includes a separate filter that excludes subscriptions still inside their backoff window.

## Edge cases

- The backoff filter must be distinct from the stale-sync filter so records still inside their backoff window are skipped while records with no backoff set remain eligible.
