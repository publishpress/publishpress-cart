# Manual refund entries keep distinct keys despite sharing one refund id

## Scenario

Manual refunds are not issued through Stripe, so multiple manual entries can share the same "manual" refund identifier. To avoid collapsing them, PublishPress Cart files each under its own distinct key. Refund log normalization must keep those unique keys intact instead of overwriting them all under a single manual entry.

## Steps

1. Start with a refund log of three manual entries that all share the "manual" refund identifier but are filed under three distinct keys.
2. Run the refund log through normalization.

## Expected result

All three entries survive normalization under their distinct keys; no manual entry is overwritten or merged despite the shared identifier.

## Edge cases

- Two or more entries sharing the same manual identifier must remain separate rows under their pre-assigned distinct keys.
