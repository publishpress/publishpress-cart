# Product metabox HTML uses canonical field and metabox ids

## Scenario

Slice 25b registers the product settings metabox as `ppcart-product-settings` and wraps fields as `rid_ppcart_*` with input `id="_ppcart_*"`. Leftover `sc-product-settings` / `rid_sc_*` / `_sc_*` ids must not render.

## Steps

1. Call `PPCart_Product_Metaboxes::add_metaboxes()` and inspect `$wp_meta_boxes`.
2. Render a representative checkbox field through `metabox_fields()`.
3. Assert canonical ids and the absence of leftover `_sc_` ids.

## Expected result

- Metabox id `ppcart-product-settings` is registered; `sc-product-settings` is not.
- Rendered markup includes `id="rid_ppcart_on_sale"` and `id="_ppcart_on_sale"`.
- Leftover `rid_sc_` / `id="_sc_on_sale"` strings are absent.

## Edge cases

- Empty post meta still emits the wrapper and input ids from the field definition.
- Form `name=` stays `_ppcart_on_sale` from slice 26.
