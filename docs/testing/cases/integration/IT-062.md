# Log rotates to a `.1` file once the max size cap is exceeded

## Scenario

The log is size-capped so it cannot grow without bound. When appending a new entry would push the active log past its maximum size, the current log is rotated to a numbered backup before the new entry is written. This verifies that rotation produces a first numbered backup file.

## Steps

1. Start with the webhook log reset and its maximum size capped low.
2. Record enough padded entries to exceed the size cap.
3. Look for the first numbered backup of the log.

## Expected result

The first numbered backup of the log exists, confirming that once the size cap was exceeded the active log was rotated into a backup and a fresh active log continued receiving writes.

## Edge cases

- Only a limited number of backup generations are kept; the oldest is deleted before the others shift up.
