# Account Orders Editor Preview Still Enforces Ownership On Detail Routes

## Scenario

The block-editor preview must not become a way around order ownership checks. Even in the preview context, if the request asks for a specific order that belongs to a different customer, the block must refuse access rather than show sample data or the other customer's real order. This guards against a preview leaking another customer's order detail.

## Steps

1. Sign in as one customer while a second customer owns a different order.
2. Preview the Account Orders block in the block editor while asking for the other customer's order.

## Expected result

- The preview shows an access-denied message.
- The other customer's real order is not shown.
- The preview does not fall back to sample data either, so the ownership check is genuinely enforced.

## Edge cases

- Skipped if the temporary customer or the second customer's order cannot be created.
