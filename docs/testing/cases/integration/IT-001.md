# Paid Charge Sync Skips Redundant Write For Already-Synced Order

## Scenario

When Stripe replays a "charge succeeded" event for an order that is already marked paid and already records the same charge, the sync must not make any redundant update to the order. This guards against webhook retries needlessly touching the order and bumping its last-modified date.

## Steps

1. Start with a paid order whose recorded transaction already matches the incoming Stripe charge.
2. Note the order's last-modified time.
3. Replay the matching Stripe charge through the sync.
4. Check the order's last-modified time again.

## Expected result

The order's last-modified time is unchanged, proving the sync skips an order that is already in step with the charge.

## Edge cases

- Applies only when both the paid status and the recorded charge already match; any difference (see IT-002) forces an update.
