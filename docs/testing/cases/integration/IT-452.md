# Cart order completion

## Scenario

A cart order holds more than one product, but the public status hooks fire one
time for the order. The work that Free does for each product must run one time
for each item.

## Steps

1. Place a Stripe cart order with two products while an extension replays the
   status hook for each item of a `main` order. One product has its purchase
   email turned off. Add one more line to the cart, then mark the order paid.
   Save the paid status again.
2. Place a cash on delivery cart order.
3. Mark a cash on delivery order paid, then refund it with restock.
4. Store a paid Buy now order that has a bump item of another product.
5. Read the merge tags of a cart order with three items, and of the context of
   one item. Read the revenue of the order for each product.
6. Use the customer-bought-product shortcode before and after the payment, with
   and without a plan.

## Expected result

`ppcart_order_complete` fires one time. The after-primary hook gets the order
type `cart`, so the extension does not replay. Integrations, product
notifications, and stock run one time for each item. One purchase email goes to
the buyer and lists both items. The download grants exist for both products. The
paid lines leave the cart, and the line that was added after the checkout
stays. The cash on delivery order runs the pending work for each item and
empties the cart. The refund revokes the download of each item and restores the
stock of each item. The order data lists every item in the merge tags, and the
context of one item lists that item. Revenue is split by product from the item
totals. After the payment the shortcode finds the product, and the plan when
asked.

## Edge cases

- A second save with the same status fires no hook, sends no email, and
  changes no stock.
- The purchase email goes out even when a product turns its purchase email off.
- A Buy now order with an item of another product still gets the order type
  `main` and its replay.
- A Buy now order has no cart revenue.
- The shortcode finds nothing before the payment, for another plan, for a
  product that was not bought, and for another customer.
