# Preview REST route is available to an authenticated editor

## Scenario

This is the positive counterpart to the preview denial cases: a user who is allowed to edit cart products must be let through the preview endpoint. It confirms the access-control rule permits, rather than blocks, an authorized editor.

## Steps

1. Sign in as a user who is allowed to edit cart products.
2. Request a checkout preview for a configured product as that user.

## Expected result

The request is allowed and the editor can render the preview.

## Edge cases

- Skipped if a configured product cannot be created.
- Skipped if no user allowed to edit cart products can be found.
