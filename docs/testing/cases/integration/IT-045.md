# Stripe subscription status maps to the local PublishPress Cart status

## Scenario

The subscription mapping translates the raw Stripe subscription status into the local PublishPress Cart status. Most Stripe statuses pass through unchanged, but a few are normalized: incomplete_expired collapses to canceled, and any unrecognized or future status falls back to past_due. This case verifies the full mapping across every Stripe status.

## Steps

1. Start with a Stripe subscription for each Stripe status value.
2. Map the subscription.
3. Compare the resulting local status against the expected value for that input.

## Expected result

The resulting local status matches the following mapping for every Stripe status:

| Stripe status | Local status |
| --- | --- |
| active | active |
| trialing | trialing |
| past_due | past_due |
| unpaid | unpaid |
| incomplete | incomplete |
| incomplete_expired | canceled |
| canceled | canceled |
| paused | paused |
| any unknown status | past_due |

## Edge cases

- Any unrecognized or future Stripe status proves the default fallback to past_due.
- incomplete_expired is the only non-canceled input that normalizes to canceled.
