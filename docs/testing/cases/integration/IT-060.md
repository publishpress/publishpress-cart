# "skipped" is a first-class, allowed webhook log status

## Scenario

"skipped" is part of the fixed set of allowed operational statuses, so it must be stored as-is rather than coerced to the fallback failure status. This verifies that a skipped outcome is written and read back unchanged.

## Steps

1. Start with the webhook log reset.
2. Record a skipped outcome for a sample event.
3. Read the log entries back.

## Expected result

At least one entry is written and the first entry's status is skipped, confirming it is a recognized status and not normalized away.

## Edge cases

- Unknown statuses are normalized to a generic failure; skipped is explicitly allowed and bypasses that fallback.
